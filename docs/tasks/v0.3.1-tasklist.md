**Objective (quoted, 3b)**: "Auto-mapper: requirements 5 and 12, plus grid preview and confidence in the review screen."

**Requirement 5 (quoted)**: "Auto-mapper `src/lib/import/map-grid.ts` implementing heuristic steps 1-6 in data-model §3 with a verb list, ingredient-name matching (singular/plural, synonyms, parenthetical removal), banner detection, and a 0-1 confidence score. Pure functions, heavily unit-tested."

**Requirement 12 (quoted)**: "Sections: map `HowToSection` and "For the ..." headings to sections; support split ingredients and bottom banners in the auto-mapper."

**Acceptance (quoted)**: "Auto-mapper reproduces the sample recipe's grid (same structure as the reference) from its plain-text steps with confidence >= 0.7." Instructions: "Make the extractor, normalizer and mapper pure functions that take strings/objects and return objects." "Sanitize all imported text ... before storing or rendering." "Do not add AI/LLM calls."

**Data-model heuristic (quoted, §3)**: 1 verb label per step from a controlled list; 2 match ingredient names (singular/plural/synonym) in step text; 3 "Reorder ingredients by first mention"; 4 "span ... contiguous range from row 0 (or first mentioned) through the last ingredient mentioned so far (cumulative "combined mixture" rule); the final step spans all rows"; 5 banner_top / banner_bottom; 5a sections; 5b split ingredients "only when the quantities are resolvable; otherwise keep one row and lower the confidence"; 6 "Compute a confidence score; low confidence leaves `view_mode = list`." §2: "Does not fit? ... the recipe stays in list view."

**In scope (spec requirement -> task)**: 5 -> T1-T6, T7 (integration); 12 -> T4, T5; grid preview and confidence in the review screen -> T10-T12; fixtures and accuracy report -> T8; ReDoS and bounded-work guarantees -> T9; carryover items scheduled for 3b -> T13, T14 (see Carryover Schedule).

**Hard rules**
- The mapper (`map-grid.ts` and helpers) is pure: no `node:*`, no `fs`, no network, no db, no React, no `Date.now()`/`Math.random()` in logic (a time budget uses an injectable clock or an operation counter, G10). Lives in `src/lib/import/`, imports only other pure modules (`ingredient-parser`, `grid/validate`, types).
- Deterministic: same input gives byte-identical output (tests assert this, including after shuffling input ingredient order, G3).
- Never lose data: every input ingredient appears in the output (split rows aside, which preserve the total), every step `detail` is verbatim, step order is preserved. Property tests assert it (T5).
- Never throws on any input: all failure paths return a list-mode result with `confidence` set and a warning code. Pipeline also wraps the call in try/catch as `runImport` does for the other stages.
- Output must pass `validateRecipeGrid` (zero errors) and `recipeInputSchema`; otherwise the proposal is dropped and the draft stays exactly as 3a produced it.
- Every regex in the mapper modules is linear-time by construction (no nested quantifiers over overlapping classes, no alternation-in-star, bounded repetition, anchored where possible). Ingredient names or step text are **never** interpolated into a `RegExp`. Matching is token and Map/Set based (T2, T9).
- Mapper-produced text shown in the UI (labels, warnings) is rendered as React text nodes; warnings are codes mapped to i18n messages, never free text from input.
- No hard-coded UI strings; all new strings in `messages/en.json` under `import.*`.
- Conventional Commit after each numbered task, no co-author trailers (owner's global CLAUDE.md). No background processes or server start commands in task commands.

| G6 | Matching rules for ingredient names ("singular/plural, synonyms, parenthetical removal"). | T2 | Normalized key per ingredient: lowercase, Unicode NFKC, strip parentheticals and text after a comma in `name` (note already separated by the parser), drop size/state modifiers from a fixed list (`large`, `medium`, `small`, `fresh`, `ripe`, `freshly`, `ground`, `chopped`, `finely`, `unsalted`, `salted`, `softened`, `melted`, `cold`, `warm`, `room temperature`, `packed`, ...) **only for the head-noun fallback**, keep them for full-phrase matching. ## Confidence scoring (definition for T6, G12)

`confidence` is a number in [0, 1], rounded to 2 decimals, computed per recipe (all sections) from counted signals. It estimates "how likely is the proposed grid to match what a person would draw", not the probability of correct parsing of text.

Signals (all computed by `map-grid.ts`, returned in `mapping.signals`):

| Signal | Definition |
| --- | --- |
| `cov` | matched ingredients / total ingredients (an ingredient is matched when at least one non-prep step mentions it at match level 1-3, or level 4 unambiguously). 1 if there are no ingredients is impossible (input requires >= 1). |
| `unamb` | 1 - (ambiguous mention weight / total mention events), where a G7 ambiguous mention weighs 1 and a half-ambiguous 0.5; 1 when there are no mention events. |
| `verbs` | column steps with a recognized controlled-list verb / column steps. |
| `splitOk` | resolved split candidates / split candidates; 1 when there are none. |
| `secFactor` | 1.00 normally; 0.85 when sections come only from ingredient groups (G16) or an ingredient is shared across sections; 0.70 when a section was merged or dropped. Multiplicative factors compound, floor 0.5. |
| `groupRefs` | number of unresolved group references (G5). |

Formula (initial weights, frozen after T8 calibration; any later change re-baselines the goldens and the corpus expectations in the same commit):

```
raw  = cov^2 * (0.55 + 0.20*unamb + 0.15*verbs + 0.10*splitOk) * secFactor
raw  = raw - min(0.15, 0.05 * groupRefs)
caps (applied with min):
  validateRecipeGrid has any error                -> result discarded, confidence = 0, mapping = null (G9), warning mapping_invalid
  fewer than 2 column steps in total              -> 0.50   (a one-column grid adds nothing)
  every column step has the same span (one distinct row_end) -> 0.55
  unmatched ingredients > 30 percent              -> 0.60
confidence = round2(clamp(raw, 0, 1))
```

Why `cov^2`: an ingredient the mapper cannot place means the visual story ("this goes in here") is wrong for that row, so a few unmatched rows must be able to push a recipe under 0.7 (for example 9 of 10 matched gives 0.81 minus nothing, 8 of 10 gives 0.64). Required properties (unit tests in T6): output in [0,1]; deterministic; adding an unmatched ingredient never raises confidence; adding an ambiguous mention never raises it; a perfect reference (all signals 1) is 1.00 for sample A.

Thresholds and UI behaviour (G13): `high` >= 0.70 opens as Grid with preview; `medium` 0.40 to < 0.70 opens as List, offers "Preview as grid"; `low` < 0.40 opens as List, preview behind "Try the grid anyway". `mapping === null` behaves as 3a. The badge shows the level word and, in a details disclosure, the numeric value and the reasons (warning codes mapped to messages). Hard requirement from the corpus (T8): **no fixture whose proposed structure differs from its expected structure may score >= 0.70** ("no confident wrong answer"); a miss with low confidence is acceptable, a confident miss fails CI.

Warning codes (closed set, all have an i18n message): `ingredient_unmentioned:<name>`, `ambiguous_name:<token>`, `split_unresolved:<name>`, `group_reference`, `step_without_ingredients`, `sections_from_ingredients_only`, `section_merged`, `ingredient_shared_across_sections`, `too_many_sections`, `input_truncated`, `time_ambiguous`, `mapping_invalid`, `mapping_budget`, `mapping_too_large`. The name/token suffix is data and is rendered as a React text node, never as markup.

## Security note (mapper input and bounded work)

The mapper consumes text that came from an attacker-controlled web page (JSON-LD, microdata, paste). It runs on the server in the request path of `POST /api/import` and must not become a CPU or memory amplification vector, and must not become an injection path to the review UI.

- **Input is sanitized text, but treated as hostile anyway**: the normalizer has already stripped tags and capped lengths (`sanitizeText`), and the pipeline passes only those strings. The mapper still enforces its own caps (G10) because paste text and future callers (3c headless) may arrive by other routes.
- **No catastrophic backtracking**: no regex over step text uses nested quantifiers, `(a|b)*`, `(.*)*`, or overlapping adjacent quantified classes; repetition counts are bounded (`{0,60}`) and patterns are anchored or sticky. Matching of ingredient names and verbs uses tokenization plus `Set`/`Map` lookups. Names are never concatenated into a `RegExp`; a lint-style unit test greps `map-grid.ts` and helpers for `new RegExp(` and fails on any use (T9).
- **Bounded time and size**: hard input caps and an operation counter budget (G10); on exceed, a list-mode result with `mapping_budget` and no exception. Complexity target: O(steps x tokens x candidates-per-first-token), with candidates indexed by first token.
- **ReDoS tests (T9)**: a registry export (`MAPPER_PATTERNS`) lists every regex used by the mapper modules; a test runs each against adversarial strings of 4000 chars (`'a'.repeat(4000) + '!'`, repeated `'( '`, `'(' x 4000` unbalanced, repeated `'1/'`, `'1 1/2 '`, `' - '`, long digit runs for temperature/time extractors, repeated `'for the '`, mixed Unicode with combining marks, zero-width characters) and asserts each completes in < 20 ms. A second test feeds maximum-size inputs through `mapGrid` end to end: 200 identical ingredient names, 100 steps x 4000 chars of a single ingredient token, 100 steps of 800 distinct tokens with 200 ingredients of 8-token names, deeply nested parentheses, 100 headings (sections explosion), and asserts completion under 250 ms (tripwire) and a deterministic result.
- **Output is data, not markup**: labels come from the controlled verb list or the sanitized 3a fallback; warning codes are a closed set; ingredient names inside warning suffixes come from sanitized input and are rendered as React text only. No `dangerouslySetInnerHTML` in the preview. The preview uses the existing `RecipeGrid` (React-escaped).
- **No new network or filesystem access**; no new dependency; no AI/LLM calls (grep evidence at the gate).
- **Resource ownership**: `GET /api/import/:id` and save keep the v0.3.0 owner-only checks; the proposal inside `draft_json` adds no new endpoint. Save still validates through `recipeInputSchema` and the grid validator server-side, so a tampered client cannot save an invalid grid (existing API tests plus T15 case).
- Security checkpoint at the end of weekend 1: engineering-code-reviewer (security focus) with security-appsec-engineer reviews T9 evidence before T7 starts.
