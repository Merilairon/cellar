### Judgements on the known issues

- **768 px, 5th column cut off:** not a violation. Measured scroll width 847 vs 732 visible (sample A). The scroll cue (edge fade plus arrow) is shown, columns are reachable, and the pre-M2 prototype behaves the same at 768 (781 vs 698 px, ingredient column 291 px). The criterion asks for visual tests at 768, which exist. It is a polish item: the ingredient column takes about 280 px at 768 (vs 138 px below 640), which is what forces the overflow. Narrowing it between 640 and 900 px would fit all five columns.
- **Sample B frosting ingredient column wider than cake's** (768: 440 vs 289 px; 1280: 594 vs 334 px; 375: both 138 px): the two tables size independently, so the two sections do not align on tablet and desktop. Not covered by any acceptance criterion. Cosmetic, non-blocking.
- **`npm run seed` not working in the Docker image:** acceptable for v0.2. Requirement 10 asks for a seed script, not a seeded container; README states the limitation and workaround, and I executed the workaround successfully. Caveat: README says to copy "a copy of the database file"; copying only `app.db` while a `-wal` file exists (or leaving a stale `-wal` in the volume on copy-back) silently loses the seeded rows. I hit exactly this (index empty after copy-back) until I removed the old `-wal`/`-shm`. README should say to stop the app first and copy back after deleting `app.db-wal` and `app.db-shm`.

### Non-blocking findings

1. **Range quantity displays lossy.** `2-3 tbsp honey` is stored and shown as `2 tbsp honey` (lower bound only, in list view and ingredient column); only `raw_text` keeps `2-3`. Documented in data-model.md and unit-tested as intentional, but a reader sees the wrong amount. Show the range (or `raw_text`) until the conversion engine exists.
2. **Scroll-cue arrow overlaps step label at 375 px** (sample B cake, the "mix" column renders as "mi" under the arrow; B-375 screenshot).
3. **e2e does not cover user deletion with recipes** (reassign/delete); only `admin.test.ts` unit tests do. I drove it manually and it works; add an e2e.
4. Carried over from v0.1: `npm audit` moderates untriaged; vitest ESM config warning; `next start` warning in e2e output.
