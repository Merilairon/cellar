## Findings

### Major

M1. `docker-compose.yml` (environment block) vs `.env.example:30-35` and README table. `RATE_LIMIT_LOGIN_MAX`, `RATE_LIMIT_LOGIN_EMAIL_MAX`, `RATE_LIMIT_LOGIN_WINDOW_SEC`, `RATE_LIMIT_REGISTER_MAX`, `RATE_LIMIT_REGISTER_WINDOW_SEC`, `HEADLESS_TIMEOUT_MS` (and `HEADLESS_ALLOW_NO_TOKEN`) are documented as operator settings, and this slice added them to `.env.example`, but compose has no `env_file` and does not forward them. Scenario: an operator on the documented Docker path sets `RATE_LIMIT_LOGIN_MAX=5` in `.env`; nothing changes, silently, on a security control. `env-docs.test.ts` only checks README and `.env.example`, so it cannot catch this. Fix: forward them with the same `${VAR:-default}` pattern, and extend the test to compare `env.ts` names against compose (with an allowlist for test-only seams such as `IMPORT_ALLOW_LOCAL_FETCH`).

### Minor

m1. `src/lib/import/uploads.ts:12-38` (`realPathInside`). Symlinked `UPLOADS_DIR` (volume mount or `/data/uploads` symlink) works: both sides are realpath'd, so stored photos still resolve. A symlinked file or subdirectory inside the uploads dir (operator moved old photos to another disk) now returns null, so photos 404 and `removeUploadFiles` refuses. Intended, but undocumented. Fix: one sentence in docs/deployment.md. TOCTOU between check and `readFile` remains (needs write access to the volume); acceptable.

m2. `src/app/api/photos/[id]/route.ts:57`. `resolveUploadPath` now costs `realpath(base)`, `lstat` and `realpath(file)` synchronously per photo request (a grid of 50 thumbs is about 150 sync syscalls on the event loop). Fix, optional: cache `realpath(base)` per process (invalidate on ENOENT).

m3. `src/app/(app)/recipes/[id]/edit/page.tsx:15-25`, `import/[id]/page.tsx:13-23`, `register/[token]`, `reset/[token]`. Only the recipe page wraps the lookup in `cache()`; these do the DB read (edit: `getRecipeFor` full tree) twice per request, once in `generateMetadata`, once in the page. Access check is identical, so no leak; cost only. Fix: reuse the `cache` pattern.

m4. `src/lib/log.ts:20-21`. Deny-list redaction is by key name: `clientIp`, `remoteAddr`, `sourceUrl`, `coverUrl`, `filename`, `path`, `title` are not redacted (only exact `ip`, `url`). No current call site logs them, but the next one will be caught only by review. Fix: match `url`/`ip` as suffixes, and add `file`, `name`, `title`, `addr`; or log through an allow-list type.

m5. `src/lib/recipes/schemas.ts:27`, `src/lib/backup/schema.ts:203`. Credentialed `source_url` now fails whole-file restore validation (`backup_invalid`) of an older own export, and blocks saving an edited legacy recipe until the URL is cleared. The importer already refused credentials, so only hand-typed URLs are affected; `@` in path or query, IDN and ports pass (WHATWG parser). Fix: accept and strip userinfo in restore, or mention in release notes.

### Nits

n1. `src/lib/log.ts:128-130` adds an `error` listener to stdout/stderr at import; if Next instantiates the module in more than 10 bundles, Node prints MaxListenersExceededWarning. Guard with a `globalThis` flag.
n2. `npm test` prints every `log()` line to stdout (restore, export tests). Mock `@/lib/log` or set `LOG_LEVEL=error` in vitest setup.
n3. `src/lib/backup/restore-load.test.ts:42-55` asserts on a `setTimeout(0)` firing mid-run: timing-dependent, passes with margin today (8 recipes x 200 rows), could flake on a very fast box. Assert on the `setImmediate` count instead.
n4. `DELETE /share-link` now works while `PUBLIC_LINKS_ENABLED=false` (behaviour change inside a logging commit); documented in the README upgrade table, good, but add it to the T14 commit notes.
