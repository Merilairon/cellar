# v0.1 (M1 Foundation) Architecture

Companion to [v0.1-tasklist.md](v0.1-tasklist.md). Decides structure and versions so dev tasks do not each re-decide them. Versions were checked against the npm registry on 2026-11-05; re-verify at T1 (`npm view`) before pinning.

## 1. Context and decisions

Small trusted group, single container, SQLite, internet-exposed behind a reverse proxy. A modular monolith with plain layered modules is enough. No hexagonal ports, no DDD aggregates in M1: auth is the only logic, and the rules are small.

| Decision | Choice | Gives up |
| --- | --- | --- |
| Structure | Modular monolith, 4 lib modules with one-way imports | Ports/adapters indirection; swapping SQLite means touching `db/` only anyway |
| Session | Random 32-byte token in cookie; DB stores SHA-256 of it as `session.id` | Cannot list a user's raw cookies (not needed) |
| CSRF | `Origin`/`Sec-Fetch-Site` check against `BASE_URL` host on all non-GET/HEAD/OPTIONS, plus SameSite=Lax | No per-form token; fine for same-site app, Next Server Actions already do an Origin check |
| Rate limit | In-memory Map, state lost on restart | Persistence across restarts; avoids a migration. Single process only |
| Token hashing | SHA-256 (tokens are 256-bit random, no need for slow hash) | None meaningful |
| Edge guard | Cookie-presence only in proxy/middleware; real validation in `getCurrentUser()` | A forged cookie passes the first gate and is stopped at the second |
| Docker base | `node:24-bookworm-slim` (glibc), not Alpine | Larger image; both native modules also ship musl prebuilds, so Alpine stays possible later |

### Next 16: middleware vs proxy
Next 16 renamed `middleware.ts` to `proxy.ts` and runs it on the Node.js runtime (the old file still works but is deprecated and keeps the edge runtime). Decision: use `src/proxy.ts`, but write it as if it were edge: no `better-sqlite3`, no `argon2`, no `src/lib/db` import, only Web APIs. Reasons: one DB handle per request path is wasteful, edge-safe code can be renamed to `middleware.ts` if the Next version is pinned lower, and it keeps the guard cheap. T1 must confirm the file name against the installed Next version and note it in the README. Whichever name applies, `tasklist` references to `src/middleware.ts` mean this file.

| Concern | proxy (cheap, edge-safe) | Node server code (Server Components, actions, route handlers, CLI) |
| --- | --- | --- |
| Public-path allow-list (`/login`, `/setup`, `/register/*`, `/reset/*`, `/r/*`, `/api/health`, `/api/auth/*` public endpoints, `_next/*`, static) | yes, pure function in `src/lib/auth/routes.ts` | n/a |
| Cookie present? else redirect `/login` | yes | |
| Validate session row, expiry, deactivated_at | no | `getCurrentUser()` |
| Admin role | no | `requireAdmin()` |
| CSP with per-request nonce, nosniff, Referrer-Policy, frame-ancestors | yes (`src/lib/security/headers.ts`, pure) | |
| CSRF Origin check | optional early reject for non-GET | authoritative check in `csrf.ts`, called by every mutating handler |
| Secure-cookie decision, client IP, trusted proxies | no | `cookies.ts`, `proxy-trust.ts` |
| Rate limiting | no | route handlers/actions |

Import rule enforced by an ESLint `no-restricted-imports` override: `src/proxy.ts`, `src/lib/security/headers.ts` and `src/lib/auth/routes.ts` may not import `better-sqlite3`, `argon2`, `src/lib/db`, `node:*`.

## 2. Module boundaries

Dependency direction (arrows = "may import"): `app/components -> auth -> db`, `app -> security`, `app -> i18n`, `auth -> security` (for IP/proxy only if needed), nothing imports `app` or `components`.

| Module | Owns | May import | Must not |
| --- | --- | --- | --- |
| `src/lib/db` | Drizzle schema, connection, migrate runner, query functions (`users.ts`, `sessions.ts`, `invites.ts`, `password-resets.ts`), ULID generation | `drizzle-orm`, `better-sqlite3`, `ulid`, `src/lib/env` | Hash passwords, read cookies/headers, know about HTTP or roles-as-policy |
| `src/lib/auth` | Password hashing (argon2id), sessions, cookies, CSRF, invites, resets, admin operations and last-admin guard, `getCurrentUser`, `requireAdmin`, public-route list | `db`, `security` (proxy resolution), `env`, `zod`, `argon2`, `next/headers` in thin wrappers only | Raw SQL; render UI |
| `src/lib/security` | Security headers builder, rate limiter, trusted-proxy resolver (`proxy-trust.ts`) | `env` (types only), `zod` | Import `db` or `auth` (keeps it reusable by M3 import and M5 public routes) |
| `src/i18n` + `messages/` | next-intl request config, locale resolution (`resolveLocale(user?)`), `messages/en.json` | `auth` (`getCurrentUser` only, in `request.ts`) | Own any query |
| `src/lib/env.ts` | zod parse of `process.env`, one exported typed `env` | `zod` | Anything else |
| `src/app`, `src/components` | Routes, pages, server actions, UI. Thin: parse with zod, call `auth`, render | all lib modules via their public functions | `db` directly for writes; raw SQL (reads through `db` functions are allowed only for display lists, and preferably via `auth/admin.ts`) |

Rule restated from the spec: controllers calling `db` repositories directly is a smell; M1 route handlers call `auth` functions. Enforce with `no-restricted-imports` (`src/app/**` and `src/components/**` may not import `src/lib/db/**` or `better-sqlite3`; documented exception: `app/api/health` calls `db/health.ts`).

Public surface per module is its `index.ts`; deep imports across modules are disallowed.

CLI (`scripts/admin-reset.ts`) imports `auth/resets` and `db` only. It must not import `next/*` (so `auth` wrappers that touch `next/headers` live in separate files from the pure functions: `auth/session.ts` pure, `auth/current-user.ts` and `auth/cookies.ts` next-bound).

Startup: `src/instrumentation.ts` `register()` runs only when `process.env.NEXT_RUNTIME === 'nodejs'`: validate env (fail fast on bad `SESSION_SECRET`), run migrations, start expired-session cleanup. Migrations are SQL files in `drizzle/` copied into the image; the migrate runner uses `drizzle-orm/better-sqlite3/migrator` (no drizzle-kit at runtime).

## 4. Environment variables

Parsed once in `src/lib/env.ts` with zod. Server-only; never `NEXT_PUBLIC_`.

| Var | Required | Default | Validation / use |
| --- | --- | --- | --- |
| `DATABASE_PATH` | no | `/data/app.db` | Non-empty path; parent dir created if missing. Dev default via `.env.example`: `./data/app.db` |
| `SESSION_SECRET` | yes | none | Min 32 chars; in production reject known placeholders (`changeme`, `.env.example` value, all same char) and refuse to start. Used for HMAC of CSRF/nonce-independent signing needs; never logged |
| `BASE_URL` | yes | `http://localhost:3000` in dev only | Valid absolute URL, no path, no trailing slash. Drives invite/reset links, redirects, CSRF origin, cookie Secure flag (`https:` => Secure) |
| `TRUSTED_PROXIES` | no | empty (trust nothing) | Comma-separated IPs/CIDRs (validated at startup). Empty: forwarded headers ignored. Set: forwarded headers honored, see the T10e spike result below. Compose Caddy profile sets it to the Docker network CIDR |
| `NODE_ENV` | set by image | `production` in image | Gates the placeholder check and CSP `unsafe-eval` |
| `PORT`, `HOSTNAME` | no | `3000`, `0.0.0.0` | Standard Next standalone vars |

`PUBLIC_LINKS_ENABLED` and the headless-browser vars belong to later milestones; do not add them now. Caveat for T10e: Next does not expose the TCP peer address in route handlers reliably; the proxy-trust resolver therefore needs the peer address from the Node request socket (custom `server.ts` is NOT wanted). T10e SPIKE RESULT (Next 16.4.5): the peer address is not available (no `request.ip`; `base-server` only does `x-forwarded-for ??= socket.remoteAddress`, so a client-sent header is indistinguishable from the peer). The fallback below is implemented in `src/lib/security/proxy-trust.ts`: with a non-empty `TRUSTED_PROXIES` the client IP is the right-most `X-Forwarded-For` hop that is not a trusted proxy; with an empty list headers are ignored and rate limits use one shared `unknown` bucket. The app port MUST NOT be published when `TRUSTED_PROXIES` is set. Original note: if the peer address is not available, fall back to treating `TRUSTED_PROXIES` as "trust the forwarded headers when the request arrives on the app port inside the compose network", and document that the app port must not be published when the Caddy profile is used.
