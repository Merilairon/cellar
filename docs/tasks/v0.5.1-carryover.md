| 3 | **No global disk cap; one global apply lock** | Stage uploads are limited per user (`RATE_LIMIT_RESTORE_MAX`, default 10 per hour; closed in the T13 conditions), but there is no cap on total disk. Residual nits from the v0.5.1 code review (recorded, not changed):

- n1: `normalizeTitle` (`restore.ts`) lowercases after NFC without a second NFC and does not collapse inner whitespace, so "Apple  Pie" and "Apple Pie" are not conflicts. Follow the tag rule or document "trim only".
- n2: `renamedTitle` can leave a trailing space before the suffix; a later file recipe literally titled "X (restored)" is not a conflict. Rename is not idempotent on a second run, by design.
- n3: restored recipes share one `updated_at`, and `ulid()` within a millisecond is not monotonic, so the original order in the recently-updated list is arbitrary. One `monotonicFactory` would keep file order.
- n4: `useRestore.ts` syncs its `live` ref in an effect, so two clicks inside one render could both start a request (the reducer guards make the second dispatch a no-op).
- n5: `restore-api.ts` sets `xhr.ontimeout` while no `xhr.timeout` is set (dead line); an early Caddy 413 that closes the socket shows as "network". No test asserts a restored recipe is found by ingredient and note search.

## 5. Documentation corrections made while writing this

- `docs/data-model.md` section 6 was a sketch (nested `metric`/`us` objects, no scope, no photos) and said the format did not exist. It is replaced by the real v1 format from `src/lib/backup/schema.ts`. Section 5 now has real rows for the four backup routes.
- The task list does not give the order of the export checks. The code checks the in-flight slot first (`409`, uses no quota), then the limiter (`429`), so a user who is both exporting and over the limit gets `409`; a failed export refunds its quota. Documented in `docs/data-model.md` section 5.
- The task list's G15 says the staged file is `<UPLOADS_DIR>/../restore/<ulid>.<json|zip>`; the code uses `RESTORE_DIR` (default `<dir of UPLOADS_DIR>/restore`). The G15 success body is `{ id, preview }`; the code also returns `kind` and `expires_at`, and the apply body also has `notes_restored`, `notes_skipped`, `ratings_restored`, `ratings_skipped` and `failed_at`. The preview has `scope`, `sections`, `ingredients`, `notes_skipped` and `ratings_skipped` beyond the G15 list. `docs/data-model.md` states the real shapes; the task list was not edited.
- The task list called the Caddy limit "260 MB" without saying how Caddy counts megabytes; fixed to 270MB (section 2 item 15).

## 6. Changelog lines (v0.5.1)

- **New endpoints:** `GET /api/export` (JSON backup; `?photos=1` for a zip with photos; `?all=1` for admins: the whole-instance backup), `POST /api/import/backup` (stage and preview a restore, `application/json` or `application/zip`), `POST /api/import/backup/:id/apply` (`{ strategy: "skip" | "rename" }`), `DELETE /api/import/backup/:id` (discard). See `docs/data-model.md` sections 5 and 6.
- **New page:** `/backup` (**Backup** in the header): export, and restore with a preview, skip or copy for recipes that already exist, and a result.
- **New backup format:** `version: 1` JSON (`scope` `own` or `all`) and a zip layout (`backup.json` first, then `photos/<id>.webp`); `migrateBackup` is the version hook. Share tokens, sessions, password hashes, invites, resets and import jobs are never exported.
- **New environment variables:** `RESTORE_BODY_MAX` (default `268435456`), `RESTORE_DIR` (default `<dir of UPLOADS_DIR>/restore`), `RATE_LIMIT_EXPORT_MAX` (default `10`), `RATE_LIMIT_EXPORT_WINDOW_SEC` (default `3600`), `RATE_LIMIT_RESTORE_MAX` (default `10`), `RATE_LIMIT_RESTORE_WINDOW_SEC` (default `3600`). In `.env.example`, `src/lib/env.ts` and the README table.
- **`src/proxy.ts` matcher:** `/api/import/backup` and its sub-paths are excluded, because the Next proxy truncates request bodies at 11 MiB. The routes authenticate and check CSRF themselves.
- **Caddyfile:** a route for `POST /api/import/backup` with `max_size 270MB` (see section 2 item 15). Raise it together with `RESTORE_BODY_MAX`.
- **Deployment:** restore uploads need a proxy body limit of at least `RESTORE_BODY_MAX`, and free disk for `RESTORE_DIR` plus the re-encoded photos ([../deployment.md](../deployment.md)).
- **No migration.** `drizzle/` still ends at `0007_note_rating_thumb.sql` (`git diff v0.4.2..HEAD -- drizzle` is empty).
- **No new dependency.** `package-lock.json` is unchanged since `v0.4.2`. `package.json` differs from `v0.4.2` in one line: the `build:seed` script gained `--external:sharp` (slice A, the Docker seed fix recorded in [v0.5.0-carryover.md](v0.5.0-carryover.md)); no dependency entry changed. `git diff v0.4.2..HEAD -- package.json drizzle` shows exactly that.
