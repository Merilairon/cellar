# v0.3.1 UX spec: import review screen, grid preview and mapping confidence (T10)

Scope: slice 3b, weekend 2 (T10, T11, T12). Design only. Read against `v0.3.1-tasklist.md` (G9, G12, G13, T10 to T12, Q2, Q4, Q6, Q8), `src/components/import/ReviewForm.tsx`, `src/components/recipe/RecipeForm.tsx`, `StepsEditor.tsx`, `RecipeGrid.tsx`, `docs/user-journeys.md` journey 1 and `docs/prototype/grid-prototype.html`.

Principles: no new editor (04b), no new dependency, existing tokens only (`btn`, `btnPrimary`, neutral/emerald/amber/red palette with `dark:` pairs, `min-h-11` targets), every imported string is a React text node, nothing depends on colour alone.

## 1. States

| State | Trigger | Initial mode | Badge | Preview |
| --- | --- | --- | --- | --- |
| `none` | `draft.mapping === null` (old draft, mapper error, budget, too large, `version !== 1`) | v0.3.0 behaviour, byte for byte | none | none |
| `high` | `mapping.level === 'high'` (>= 0.70) | Grid, proposal applied | "Good match" | open |
| `medium` | 0.40 to < 0.70 | List, page order | "Check the mapping" | none until "Preview as grid" |
| `low` | < 0.40 | List, page order | "Could not map reliably" | none until "Try the grid anyway" |

The UI trusts `mapping.level`; it never recomputes it from `confidence`. Sub-states while a proposal exists: `grid` (applied), `grid-edited` (any `sections` change since the last structure load), `list` (user went back or started in list).

## 2. Layout

One column at every width (the form is `max-w-3xl`). Order inside the `header` slot:

1. Intro paragraph (existing).
2. Duplicate notice (existing).
3. **Mapping panel** (new, only when `mapping !== null`): badge, state line, mode line, actions, details disclosure, fix hint, then the preview.
4. Source, import warnings ("Notes about the page", existing), cover, tags, attribution (existing, unchanged).

The panel goes before the page notes because it is the one decision the user must make on this screen.

```
375 px (16px gutter)             768 px                    1280 px
+-----------------------+   +-------------------------+   +-------------------------------------+
| intro                 |   | intro                   |   | intro                               |
| [badge: icon + text]  |   | [badge] state line      |   | [badge] state line                  |
| state line            |   | Will be saved as: Grid  |   | Will be saved as: Grid              |
| Will be saved as: Grid|   | [Use list view][Reset]  |   | [Use list view instead] [Reset]     |
| [Use list view inst.] |   | > Why this score        |   | > Why this score                    |
| [Reset to proposal]   |   | fix hint                |   | fix hint                            |
| > Why this score      |   | > Grid preview (open)   |   | > Grid preview (open, up to 72rem)  |
| fix hint              |   |  [scrolls sideways]     |   |  [table, sticky ingredient column]  |
| > Grid preview (open) |   | form fields (max 48rem) |   | form fields (max 48rem, left)       |
|  [scrolls sideways]   |   +-------------------------+   +-------------------------------------+
| form fields           |
+-----------------------+
```

- Buttons stack full width at 375, wrap in a row from 640 (`flex flex-wrap gap-2`). All targets `min-h-11`.
- The panel is `max-w-3xl` at 375 and 768; the preview wrapper may widen to `max-w-6xl` at >= 1280 so the table needs less sideways scroll. The form below stays `max-w-3xl`.
- The grid keeps its own `ScrollRegion` (horizontal scroll, sticky ingredient column, as on the recipe page). No vertical max-height (nested scroll traps).
- Optional, cuttable (E1): at >= 1280 put the preview in a sticky right column so spans can be edited while watching it. Needs an `aside` slot in `RecipeForm`. Not required for acceptance.
- Panel container: `rounded border-2 p-3`, colours per level (section 3). The preview lives inside the same bordered container so the relation is clear.

## 3. Confidence badge

Always three things together: a distinct icon shape, a text label, and a border/background colour. Colour is never the only carrier. Icons are inline SVG with `aria-hidden="true"`; the label is real text, so a screen reader reads "Good match" without any `aria-label`.

| Level | Icon | Label (en) | Description line (en) | Light | Dark |
| --- | --- | --- | --- | --- | --- |
| high | check in circle | Good match | We placed every ingredient in the steps that use it. Please give the preview a quick look. | `border-emerald-700 bg-emerald-50 text-emerald-900` | `dark:border-emerald-400 dark:bg-emerald-950 dark:text-emerald-200` |
| medium | triangle with exclamation | Check the mapping | We could place most ingredients, but some steps are unclear. Preview the grid before you choose it. | `border-amber-700 bg-amber-50 text-amber-900` | `dark:border-amber-400 dark:bg-amber-950 dark:text-amber-200` |
| low | circle with cross | Could not map reliably | We could not tell which ingredients go with which steps. The recipe will be saved as a list unless you try the grid yourself. | `border-red-700 bg-red-50 text-red-900` | `dark:border-red-400 dark:bg-red-950 dark:text-red-200` |

Pairs mirror classes already used in the app (duplicate notice, error summary); verify AA with axe on every state in both themes (T12). The numeric score is not in the badge; it is in the details disclosure (section 7). Badge markup: `<p>` with icon and label, not a button, not focusable. "Good match" does not claim correctness; the description asks for a look.

## 4. Choosing grid or list on save (`view_mode`)

No radio group. The mode is a visible fact plus one or two actions, all labelled with plain words:

- A permanent line in the panel: **"Will be saved as: Grid"** or **"Will be saved as: List"** (part of the `role="status"` state line, section 8).
- Mode `list` (medium): button **Preview as grid** (`btn`, primary emphasis allowed). Applies the proposal, mode becomes `grid`.
- Mode `list` (low): the same action is a secondary, text-weight control **Try the grid anyway** (`btn` without emphasis), below the reasons, which are shown open.
- Mode `grid`: button **Use list view instead** (returns to page order, mode `list`). Plus **Reset to proposal** when `grid-edited`.
- Mode `list` after going back (any level): the button reads **Preview as grid** (high and medium) or **Try the grid anyway** (low), same slot, so users can switch back and forth.

Save behaviour (T11): `target.extra = { import_cover, view_mode: mode }` only when `mapping !== null`; for `none` nothing is added (API default, identical to v0.3.0). Explicit `view_mode: 'grid'` makes the API return 422 with the validator errors if spans are invalid; the existing red error summary lists them with links to the fields. This is the safety net; it never saves a broken grid. Explicit `view_mode: 'list'` always saves, with whatever spans are in the fields (empty by construction after "Use list view instead").

The tasklist rule "`mapping !== null` low: nothing saves as grid unless every span is valid, which the API enforces" holds unchanged.

## 5. Behaviours

### 5.1 Preview as grid / Try the grid anyway
1. Build the form sections from `mapping.sections` (0-based spans to 1-based strings, rows already in proposal order, sections created).
2. Mode becomes `grid`; state line: "Proposal applied. Saving as grid."
3. Preview opens; focus moves to the preview heading (section 8).
4. Medium/low: nothing else changes; the badge and reasons stay.

### 5.2 Use list view instead
Rebuild sections from `draft.sections` (page order, empty spans). Mode `list`. State line: "Showing the list as imported. Saving as list." Focus returns to the button that now occupies the same slot ("Preview as grid"/"Try the grid anyway").

### 5.3 Reset to proposal
Only visible in `grid-edited`. Rebuild from `mapping.sections`; state line "Proposal restored." Focus to the preview heading.

### 5.4 Confirm before replacing edits
If the current `sections` differ from the last loaded structure (`grid-edited`, or text edited in list mode), the three actions above first show an inline confirm in place of the buttons, not a modal:

> "This replaces your changes to ingredients and steps. Title, description and other details are kept." [Replace] [Keep editing]

Focus goes to **Keep editing** (the safe default); Escape = Keep editing; after Keep editing, focus returns to the originating button. When nothing was edited, no confirm is shown. Edits outside `sections` never trigger it.

### 5.5 Edited indicator
Any change to `sections` while in `grid` sets `grid-edited`. State line: "Proposal applied, with your changes. Saving as grid." The badge still describes the original proposal; add the line to the details disclosure: "The score is for the proposal, not for your edits." (one i18n key).

## 6. How the step-to-ingredient mapping is shown, and how to correct it

**Shown.** In the preview, the real `RecipeGrid`: each ingredient is a row, each column step is a cell spanning the rows it uses (cell text = step label, temperature and time via `formatStepParams`; sr-only text "uses rows from X to Y", already in the component). Banners are full-width rows above or below. Below, in the form, `IngredientTextarea` already shows "Row n" next to every parsed ingredient and `StepsEditor` shows "Step n" fieldsets, so grid and editor share row and step numbers. Preview column headers use "Step n: label" (existing `recipe.grid.stepHeader`).

**Correct a wrong mapping (no 04b editor).**
1. Find the step in the form (Step n matches the column header).
2. Change **Ingredient row from / to** (existing 1-based number inputs, disabled for banner steps) or change **Kind** (banner top / column / banner bottom, existing select) or the step **label**.
3. The preview redraws on every keystroke, no request. Invalid values (end before start, beyond the last row, empty on a column step) replace the grid with the validator messages (section 9) instead of a broken table.
4. If it is not worth fixing: **Use list view instead** (the explicit reject). There is no per-step accept/reject; it is not needed.

Fix hint (always visible under the details, one line, **not** cuttable): "To correct the grid, change the ingredient row numbers in a step below. The preview updates as you type. Avoid reordering ingredient lines; change the numbers instead."

Optional read-only hint per step under the two span fields (E2, cuttable): "Rows 1 to 3: flour to eggs" (`recipe.form.step.spanHint`), derived from the current ingredient lines. Needs a small `StepsEditor` prop; skip if time is short.

- Reasons = `mapping.warnings`, one `<li>` each, message from `import.warning.<code>` (section 11). Suffix data (`name`, `token`) is passed as an ICU value and rendered as a text node. Show at most 5, then "and {count} more" (the code set is closed but `ingredient_unmentioned` can repeat up to 200 times).
- No warnings and not high: a single fallback reason "No single problem stood out; there was not enough in the steps to place the ingredients." (`reasonNone`).
- The existing "Notes about the page" list (`draft.warnings`) stays separate and unchanged; it additionally receives `mapping_invalid`, `mapping_budget`, `mapping_too_large` when `mapping === null`.

## 8. Keyboard and screen reader behaviour

Tab order: mapping buttons, "Why this score" summary, preview skip link, preview region, then the form (title first). No focus traps; no modal.

- Badge: plain text, not focusable. The panel is `<section aria-labelledby>` with an `h2` "Automatic grid" (visible heading, the badge sits under it).
- **State line**: one element, always in the DOM, `role="status"` (polite), visible (not sr-only), content = state sentence + "Will be saved as: ..." Updates on apply, back-to-list, reset, first edit. Because it is present at mount, nothing is announced on page load (no chatter); the badge and description are read in normal reading order.
- **Focus rules**: after Preview/Try/Reset, focus the preview `h2` ("Grid preview", `tabIndex={-1}`) and scroll it into view; after Use list view, focus the button that takes its slot; confirm opens on **Keep editing**; Keep editing returns focus to the originating button. Never leave focus on an unmounted element.
- **Preview**: native `<details>` with summary "Grid preview" (Enter/Space toggles). Inside, `RecipeGrid` (`detailMode="inline"`) keeps its v0.2 semantics: one `<table>` per section with caption and `th scope`, `ScrollRegion` (`role="region"`, `tabindex=0`, arrow keys scroll), each step cell a button with `aria-expanded` (reveals the full step text, as on the recipe page). Tables have many tab stops, so the first element in the preview is a **skip link** "Skip the preview and go to the recipe fields" (`href` to the title field id); visible on focus.
- Preview heading `aria-describedby` a short sr-only summary: "{steps} steps over {rows} ingredient rows in {sections} parts." Not repeated per update, only when the preview is (re)drawn from Apply/Reset.
- When the grid cannot be drawn, the messages block is a `role="status"`-free static list (the state line already announced "Saving as grid"; add "The grid cannot be shown yet." to its text via the same region while invalid; update only on transition valid/invalid, not per keystroke).
- Disclosures and buttons are native elements; visible focus ring from the existing styles; target size >= 44px.
- No hover-only information anywhere. Motion: none (no animation to reduce).
- Screen reader testing is **not performed** in this slice (stated in T12); the above is the intended behaviour, verified only by axe and a manual keyboard pass.

## 9. Empty and error states

| Situation | Behaviour |
| --- | --- |
| `mapping === null` | No panel, no preview. Page notes list may contain `mapping_*` messages. Everything else identical to v0.3.0 (`ReviewForm.test.tsx` untouched). |
| Grid mode, a section has no column steps | Preview for that section replaced by "No step in this part is linked to ingredients yet." Other sections still draw. |
| Grid mode, `validateRecipeGrid`/`validateSection` errors | Preview body (all sections) replaced by "The grid cannot be shown yet. Fix these before saving as a grid, or use the list view:" and a list of validator messages, each "Step {n}: {message}" as a link to the field (same `locate` pattern and `errorMessageKey` texts as the error summary). Wording reuses existing `recipe.errors.*` messages; no new validator texts. |
| Grid mode, zero ingredient lines | Same block; message "Add at least one ingredient." (existing key if present). |
| Save returns 422 in grid mode | Existing red summary (focus moves there). Append one line to the panel state line: "The grid is not valid; fix the steps or use the list view." Save is never silently downgraded to list. |
| Save fails (network/500) | Existing `import.review.saveFailed`. Nothing new. |
| Confirm pending and user navigates away | Native behaviour; no draft is lost server side (the job persists). |
| Draft re-opened (reload) | The form state is client-only today: re-open restarts from the initial state for the level. Edits are lost on reload (same as v0.3.0). Not changed in 3b. |
| Very long labels, names | Wrap (`overflow-wrap:anywhere`); table cells already do. |
| Tiny proposal (< 2 column steps) | Mapper caps at 0.50 (medium); preview works; no special state. |

No loading state: the proposal arrives with the draft.
