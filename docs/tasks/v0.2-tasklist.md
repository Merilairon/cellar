# v0.2 (M2 Recipe View) Development Tasks

## Specification Summary

**Source**: [milestones/02-recipe-view.md](../../milestones/02-recipe-view.md), [PROJECT.md](../PROJECT.md), [RELEASE_PLAN.md](../RELEASE_PLAN.md) (Definition of Done), [TASK_ASSIGNMENTS.md](../TASK_ASSIGNMENTS.md) (v0.2 table), [data-model.md](../data-model.md) (§1 recipe/section/ingredient/step, §2 grid model, §5 API), [PRD.md](../PRD.md) §4, [prototype/grid-prototype.html](../prototype/grid-prototype.html) (visual reference only, do not copy code).

**Objective (quoted)**: "Create, view, and delete recipes manually, with the signature **grid view** (matching the reference table) and a list-view fallback."

**Technical stack** (already in repo from v0.1): TypeScript strict, Next.js 16 App Router (`src/proxy.ts` gate), Tailwind 4, Drizzle + better-sqlite3 (`src/lib/db/`, migrations in `drizzle/`), zod 4, next-intl (`messages/en.json`), Vitest (`src/**/*.test.ts`, `tests/unit/`), Playwright (`tests/e2e/`, port 3100, fresh DB per run, serial specs), tsx scripts (`scripts/`).

**Target pace**: M2 gets two weekends (RELEASE_PLAN). Suggested split: weekend 1 = T1-T7 (data, parser, API, grid, list, recipe page); weekend 2 = T8-T17. Re-split if it overruns.

**Build order (spec "Instructions for LLM")**: data layer and parser first with tests, then API, then components, then pages. Tasks below follow that order, then seed, responsive, copy/visibility, user deletion, a11y, visual tests, docs.

**Hard rules from the spec**
- "Keep `RecipeGrid` presentational (props in, markup out); put span validation in `src/lib/grid/validate.ts` with unit tests."
- "Do not implement unit conversion, import, search, or sharing here." Out of scope: unit conversion or scaling (display only what is stored), URL/paste import, search/tags beyond a "tags placeholder", share-link (`/r/:token`, `share-link` endpoint), photos, notes, ratings, grid drag editor (M4), print. In scope despite the word "sharing": the `visibility` field and `PUT /api/recipes/:id/visibility` and `POST /api/recipes/:id/copy` (requirement 12).
- "Use a snapshot or visual test of the brownie fixture to protect the grid layout." The fixture is the self-written sample, not third-party text.
- Carried over from v0.1: data access only in `src/lib/db/`, no raw SQL in route handlers, zod on all inputs, no hard-coded UI strings (keys in `messages/en.json`, enforced by `tests/unit/i18n-keys.test.ts`), `isCsrfSafe` on every mutating handler, responsive at 375 / 768 / 1280 px.

**Agent name shorthand**: lead/support names come from the v0.2 table in TASK_ASSIGNMENTS.md. Rows used: "Recipe CRUD API and queries", "Grid component + list view", "Responsive layout and visual system", "Grid table semantics, keyboard navigation", "Visual tests at 375 / 768 / 1280 px", "Gate". Items with no table row (parser, forms/pages, seed, user deletion, docs) use the nearest row, marked "(nearest row)".
