## Verdict: NEEDS WORK

The product itself held up: every gate I could run passed on this exact tree, twice for the slow one. The verdict is not READY because three conditions the tasklist sets for the tag are not met on the tree today (blockers below). All three are small; none needs new feature code.

### Blockers (before the tag)

1. **Security review sign-off condition not met: M1 has no written owner decision.** T15's acceptance rule is "Medium fixed or owner-accepted in writing". `v1.0-carryover.md` lists M1 (a member can push the instance past the 32 MiB export cap so the admin `?all=1` export answers 413), Q4, Q7 and Q16 as "awaiting owner". Q4, Q7 and Q16 are recorded residuals with an "accept" recommendation; M1 is a Medium. Needed: the owner's written accept (or a fix) for M1, and for Q4/Q7/Q16 per the review.
2. **`npm audit --omit=dev --audit-level=high` no longer passes, so T15 checklist item 9 does not reproduce.** The review recorded `found 0 vulnerabilities` for the committed lockfile. Today (advisory database newer than the review) it reports 2 high findings: `picomatch` ReDoS (GHSA-fc5q-39xc-vjpf) at `next-intl@4.14.9 > @parcel/watcher@2.6.0 > picomatch@4.0.7`, exit code 1. The path is a file watcher dependency of next-intl, not on any request path of this app, so the real exposure looks nil, but the gate item is a command and it fails, and the scheduled CI `audit` job will go red. Needed: `npm audit fix` / an override with the lockfile re-committed and the gate re-run, or a written owner acceptance with the advisory id. Full run showed 22 findings with dev dependencies (10 moderate, 12 high, `vite` and friends), not part of the gate command.
3. **T18 documents are not done on this tree.** `docs/RELEASE_PLAN.md` still says "**v1.0 (slice C ...) is not started**", the v1.0 table row has no status, the v1.0 Release Checklist boxes are all unticked and no link to the v1.0 tasklist, code review, security review, a11y audit/fixes or this file exists. `docs/tasks/v1.0-carryover.md` (21 lines) holds only the security and code-review residuals; the T18 list is missing: Q15 result per device, the deferred v0.4.2 items restated (Q14), the not-tested list (Pi, Firefox, Safari, screen readers, arm64, real printers, real Traefik), and the feedback window for checklist item 6. The tasklist T18 box is unticked. These are the PM deliverables of T18; they must exist before the tag, and they must mirror the results here (including the audit finding and the owner decisions).

### Not blockers, recorded

- Restore re-encodes photos (by design, G17/R12). On the round trip below one 640x480 photo came back with a different byte stream (A 634 B, B 632 B), same dimensions, decoded samples differ by at most 4 of 255 on 242 of 921 600 samples; two other photos were byte-identical. "Identical recipes" in criterion 3 holds for every recipe field, grid spans and photo order/cover; photo pixels are near-identical, not bit-identical. `grep -i re-encod README.md` finds nothing; it is stated only in `docs/deployment.md`. Worth one README sentence in the backup section.
- `x-powered-by: Next.js` is still sent on pages and on the public 404 (review I1, recorded as not done).
- Residuals m2, m3, m5, n1, n2, n4 stay as recorded in the carryover.
