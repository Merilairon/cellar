## Summary

Solid slice. `canRead`/`canWrite` have zero remaining references in `src` (grep), every page and route that
returns a recipe goes through `canView`/`canEdit`, and every caller of `getRecipeFor`, `createRecipeFor`,
`updateRecipeFor` and `updateGridFor` passes `shareContext()` (pages: detail and edit; routes: recipes, recipes/[id],
grid). The service default is fail-closed (`NO_SHARE_CONTEXT`: links off, no token), so a forgotten caller hides
share state instead of leaking a token. The anonymous path is tight: format gate (22 chars base64url, no `m` flag),
unique-index lookup, `canView` re-check with `timingSafeEqual`, one `null` for every failure, field-picked
`PublicRecipe`, `noindex`, `no-referrer` (also for encoded `/r` paths), per-IP /64 limiter, `PUBLIC_LINKS_ENABLED`
enforced in the page, in both share-link routes and in `toApiShare`. The token appears only in `toApiShare`
(owner only); lists and search never select it. R5 holds: `setRecipeVisibility` and `setShareToken` no longer stamp,
and nothing in the client relied on the old bump (`base_updated_at` is read from the save response; list order
tolerates it; `RecipeView` compares stamps only after grid saves). Copy sets `shareToken: null`.

Verdict: **APPROVE WITH CONDITIONS.** 0 blockers, 0 major, 4 minor, 4 nits. Condition: decide and document m1.

## Findings

### Minor

m1. `src/app/api/recipes/[id]/share-link/route.ts:30-31`. DELETE returns 403 `public_links_disabled` when links
are off. An owner cannot revoke a link while the operator has links disabled; the token stays stored and becomes
live again when the flag flips back. Scenario: link leaked, operator disables links as a stopgap, owner revokes
(refused), operator re-enables, the "revoked-in-intent" link works. Fix: allow revoke regardless of the flag (it
only clears data), or state in `docs/deployment.md` that tokens survive disabling and that re-enabling revives them.

m2. `src/lib/recipes/service.ts` (`share?: ShareContext` trailing params, lines ~279, 294, 316, 358). Optional
trailing parameter means the next caller that forgets it silently reports "links off" and `share.enabled=false`
(UI would show the link as off while it is live). Today all callers pass it, so no bug now. Fix: make it required
for the route-facing functions (tests can pass an explicit off context) or add a test that greps routes/pages.

m3. `src/app/globals.css` print block (`main > div.lg\:grid > div:nth-child(2)`, `main > div.lg\:grid > div:first-child > p`,
`body button:not(.rg-stepbtn)`, blanket `body * { color/background !important }`). All of it sits inside
`@media print` or `@page` (verified; the only screen change is `.ck-wake:empty::before`, intended), so nothing
leaks to screen. But the structural selectors couple print to Tailwind class names and child order of the recipe
page; a reorder in `page.tsx` silently prints the photo panel or hides the title. Fix: add `print:hidden` /
`data-print` hooks in markup instead. The 7pt table floor for 11+ columns is small for kitchen use; acceptable
given the measured trade-off, worth a user check.

m4. `src/components/recipe/SheetDialog.tsx:62`. The new `if (e.currentTarget.open) return;` guard is shared by
the grid editor and cook mode. It is correct for the Escape-then-reopen race, but there is no unit test aimed at
the guard in those two consumers; only the share e2e exercises it. Add a small component test (close event while
`open` is true must not call `onClose`).

### Nits

n1. `src/proxy.test.ts` encoded-path test: `'/%2572/x'.replace('%2572', '%72')` is a no-op duplicate of
`/%72/abc`; it does not test double encoding. Remove or make it assert that `/%2572/x` is not a share path.

n2. `src/lib/recipes/routes.test.ts`: the mutable `state.linksEnabled` is reset but never set to `false` in this
file (the disabled case is covered in `share-link.test.ts:160`). Drop the flag or add the case.

n3. `src/lib/security/public-limit.ts:24-35` `limiterKey`: the `ip.includes('::') ? groups.length > 4 : false`
branch plus the padding branch is hard to read; correct for the cases in `proxy.test.ts` (`::1`, compressed,
full), but a short comment with three examples would help. IPv4-mapped input is normalized upstream
(`proxy-trust`), so no shared bucket.

n4. `src/components/recipe/public/PublicRecipeView.tsx` footer `<p>` class order (`print:hidden` mid-list); cosmetic.
