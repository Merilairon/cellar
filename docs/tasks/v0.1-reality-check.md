# Retry 1 report (superseded, kept for history)


Date: 2026-11-05. Commit under test: 6157672 (release/v0.1), tested from a fresh `git clone` (committed state only, fresh `npm ci`, fresh Docker build, fresh volumes). Host: Linux amd64, Node 24.15.0, Docker 29.9.2, Compose 5.7.0.

## Verdict: NEEDS WORK

Everything functional passed. One documentation defect breaks the README's own Docker instructions when followed literally with a non-default `APP_PORT`, so the "README accuracy" and "docker compose up works from a clean checkout" items cannot be certified yet. Fix is small (docs or compose default); re-check afterwards.

## Blockers

1. **README `APP_PORT` instruction is incomplete and fails silently.** README says "change the host port with `APP_PORT` in `.env`". Evidence: with `APP_PORT=3412` and `BASE_URL` left at `http://localhost:3000` (the `.env.example` value), `/api/health` returns 200 and pages render, but every POST (setup, login) is rejected by the origin allowlist: `POST /api/auth/login` with `Origin: http://localhost:3412` returns 403, and the browser setup form ends on a blank `/api/setup`. First-run is impossible and gives the user no hint. Fix: document that `BASE_URL` must be changed together with `APP_PORT` (and in `.env.example`/compose comment), or derive the BASE_URL default from `APP_PORT`, or make the 403 page explain the origin mismatch. With `BASE_URL=http://localhost:3411` matching, everything below passed.

## Non-blocking findings

- Compose hard-codes subnet `172.28.0.0/24` for the default network even without the caddy profile. A second compose project (or any host network overlapping it) fails with "Pool overlaps with other one on this address space" (hit when I tried a second project name). Only the Caddy profile needs the fixed IP.
- `npm run test:e2e` prints `"next start" does not work with "output: standalone"`; the test still passes, README documents `npm start` for production which has the same warning. Cosmetic, but README's `npm run build` then `npm start` row is questionable.
- `npm audit`: 12 moderate vulnerabilities in the lockfile (not triaged here).
- Vitest warns about `vitest.config.ts` being ESM syntax in a CommonJS package. Cosmetic.
- `/data/uploads/` is not created (spec "Technical Context" mentions it); nothing uses it in v0.1. Not a defect for this milestone.
- `/login` returned 307 on a fresh database (redirect, presumably to `/setup`) and `/recipes` etc. redirect to `/login`; consistent with design, noted only because "public" route status differs by DB state.
- Image size 428 MB (`recipe-book:local`); not a stated requirement.
