## 1. Share dialog (requirement 2; T5; G4, G8, G10)

### 1.1 Entry: the Share button and its state chip

- **Share** (`btn`, share icon + text "Share", `aria-haspopup="dialog"`) replaces `VisibilityControl` in the actions slot. Visible to `can_edit` only (owner or admin; readers never see it). Row order in `RecipeView`'s actions row: **Cook · Edit · Delete · Edit photos · Share · Print · Edit grid layout** (readers: **Cook · Save a copy · Print**). Print is T6's button (section 4).
- A **state chip** follows the button (plain text, `text-sm`, `--rg-muted`, not a control): "Private", "All users", "Public link", or "All users · Public link". It updates when the dialog changes something. It is not a live region (the dialog's status announces changes); sighted users see the sharing state at a glance without opening the dialog.
- The chip and the button hide while the grid editor is open (the editor replaces the read view).

### 1.2 The dialog surface

- Built on `SheetDialog` (native modal `<dialog>`, focus trap, Escape, backdrop click, scroll lock) with a new variant class `share-dialog`:
  - **< 640 px**: the existing bottom sheet (`dialog.rg-sheet`: bottom-anchored, full width, `max-height: 80dvh`, `overflow-y: auto`, `overscroll-behavior: contain`, 16 px body padding).
  - **>= 640 px**: centred (`margin: auto`, `width: min(32rem, calc(100vw - 2rem))`, `max-height: 90dvh`, `border-radius: 12px`, 24 px body padding). Same element, same markup; only CSS differs.
- **Focus on open** goes to the `h2` ("Share recipe", `tabindex="-1"`), as cook mode does. Tab then reaches **Close** first. **Close** (X icon + visible text "Close", 44 px) sits top right of the header row.
- **Close paths**: Close button, Escape, backdrop click. All return focus to the **Share** button. An open inline confirm is simply dropped (nothing was sent). If anything changed while open, the component calls `router.refresh()` **once on close** (not per action), so the page behind does not re-render under the dialog.
- The dialog opens with the data already on the page (`visibility`, `share: { enabled, url }`, `public_links_enabled`, `isImportedUnedited` passed from the server component); there is **no loading state on open**.

### 1.4 Behaviour per control

**Section 1, "Who can see this"** (`<fieldset>` with `<legend>`; two native radios, 44 px rows, helper text under each as `aria-describedby`):

- Changing the radio sends `PUT /api/recipes/:id/visibility` at once (optimistic: the radio moves, the summary updates). Failure: the radio moves back, the summary returns, and an inline alert under the group says "Could not save. Try again." (401/403/404: "You can no longer change sharing for this recipe."). The request is not debounced (a radio change is deliberate).
- "All users" has `aria-describedby` = its helper **plus** the copyright notice id when the notice is rendered (F2).
- The readers' "Shared by {name}" notice on the recipe page is unchanged (T5).

**Section 2, "Public link"**:

- Heading `h3` "Public link"; a `<button type="button" role="switch" aria-checked>` with `aria-labelledby` pointing at the heading, a visible track + knob (44 x 24 px hit area padded to 44 x 44) and the visible state word **"On"/"Off"** beside it (never colour alone). `aria-describedby` = the helper line ("Anyone with the link can read this recipe without signing in.") plus the copyright notice id when rendered.
- **Off → On**: `POST /api/recipes/:id/share-link`. While pending the switch is `aria-busy="true"` and `aria-disabled="true"`, the knob stays off, the state word reads "Turning on…". Success (201 `{ url }`): the switch is checked, the field, **Copy link**, **New link** appear, the summary updates (announced), and **focus moves to Copy link** (the next action nine times out of ten). Failure: the switch stays off; inline alert "Could not turn on the public link. Try again." 403 `public_links_disabled` (the admin turned links off after the page loaded): the switch is replaced by the one-line note of section 1.5.
- **On → Off** (F3): the switch does **not** flip yet; it becomes `aria-disabled="true"` (still checked) and an inline confirm appears under it: "Turn off the public link? Anyone who has it will no longer be able to open it." **[Turn off]** (`btnDanger`) **[Keep]** (`btn`), focus on **Keep**. Keep: the confirm closes, focus returns to the switch. Turn off: `DELETE share-link`; while pending the confirm's buttons are disabled; success (204): the field and buttons disappear, the switch is off, the summary updates, focus goes to the switch. Failure: the confirm closes, the switch is still on, inline alert "Could not turn off the link. It still works. Try again."
- **URL field**: `<input type="text" readOnly value={url} aria-label="Public link">`, `font-mono text-sm`, full width; focusing or clicking it selects the whole value (`select()` on focus) so Ctrl+C always works; the value is never truncated with CSS (it scrolls inside the field if the host name is long).
- **Copy link** (`btn`): `navigator.clipboard.writeText(url)`. Success: the visible word "Copied" appears right of the button for 2 s and the status reads "Link copied." for the same time, then returns to the summary sentence. Not available (insecure context, denied): the field is focused and selected and the status reads "Select the link and copy it with Ctrl+C." (on `pointer: coarse`: "Select the link and copy it."). No `document.execCommand`.
- **New link** (`btn`): inline confirm "Make a new link? The old one stops working immediately." **[Make new link]** (`btnPrimary`) **[Keep]**, focus on Keep. Make new link: `POST share-link` (the endpoint rotates when a link exists, G10); pending: buttons disabled; success: the field shows the new URL, the status reads "New link ready. The old link no longer works." for 3 s then returns to the summary, focus goes to **Copy link**. Failure: alert "Could not make a new link. The old link still works."
- Only one inline confirm can be open at a time; opening the other closes the first (nothing sent).
- **Pending states** never disable the Close button; a close during a request lets the request finish and refreshes on completion (the state chip on the page follows the server).

### 1.5 `PUBLIC_LINKS_ENABLED=false` (G4, Q5)

Section 2 renders the heading and **exactly one line**, no switch, no field: "Public links are turned off on this Cellar by its admin." (`--rg-muted`, with an info icon `aria-hidden`). Any stored token is inert and not mentioned (re-enabling restores it unchanged; the owner then sees it as "On"). Section 1 works normally. The state chip never says "Public link" while disabled.

### 1.6 Keyboard path (dialog)

Share (Enter/Space) → heading focused → Tab: Close → Private → (arrows move within the radio group and **select**; a selection saves) → switch (Space or Enter toggles; off direction opens the confirm whose Keep is focused; Tab inside the confirm: Keep → Turn off; Escape closes the dialog and drops the confirm) → URL field (Ctrl+C copies the selected value) → Copy link → New link → (confirm: Keep → Make new link). Shift+Tab reverses. Escape and Close return focus to Share. No roving tabindex, no custom key handling beyond the switch (which is a `<button>`, so Space/Enter are native).

## 2. Copyright / attribution notice (requirement 2; G8; PRD section 9)

- **Rule**: rendered when `isImportedUnedited(recipe)` is true (`source_url` set and `updated_at === created_at`, Q3 default; a pure function with tests, T2). Not rendered for manually created recipes, fresh copies (a copy of an imported recipe has equal stamps and a `source_url`, so it **does** count as imported and unedited: correct, it is the same text), or imported recipes that were edited.
- **Placement**: a static block between the summary status and section 1, so it precedes both sharing actions (F2). `role="note"`, `aria-labelledby` its title; `--ge-warn-bg` / `--ge-warn-ink` / 1 px `--ge-warn-line` border, a triangle icon `aria-hidden` plus the visible title; 8 px radius; body text `text-sm`.
- **Never blocking**: no checkbox, no "I understand" button, no delay; the radios and the switch work exactly as without the notice. **No "do not show again"**: it is shown on every open while the rule holds (editing the recipe removes it, which the text says).
- **Source rendering**: `{source}` is `source_name` when set, else the host name of `source_url` (`safeHttpUrl` first; `new URL(...).hostname`), as a text node, no link inside the notice (the link is on the public page). When neither yields a name the fallback body is used.

**Final wording (legal, section 9)**:

- Title: **"This recipe was imported and not edited"**
- Body: **"It came from {source}. The text of a recipe (descriptions, steps) may be protected by copyright, even when the ingredient list is not. Publishing it republishes that text, and you are responsible for it. The public page names the source and links to the original, but anyone with the link can read it. Search engines are asked not to index it. Rewriting the recipe in your own words removes this warning."**
- Fallback body (no source name or host): **"It was imported from another website. The text of a recipe (descriptions, steps) may be protected by copyright, even when the ingredient list is not. Publishing it republishes that text, and you are responsible for it. Anyone with the link can read it. Search engines are asked not to index it. Rewriting the recipe in your own words removes this warning."**

On a 375 px sheet the notice is about nine lines; that is accepted (it is the one surface where the owner must read). The sheet scrolls; the heading stays visible as the first element.

## 3. Public page `/r/:token` (requirement 3; T4; G7; R11; Q2)

### 3.1 Decisions

- **No app navigation, no login link, no "Cellar" word linking to `/`** (recommendation accepted). A guest who follows such a link only reaches the login page, which advertises the instance for no benefit; the footer sentence names "a private recipe book" instead. No theme toggle either (the root layout applies the theme cookie or the system preference, so a guest gets their system theme; the surface stays minimal).
- **`<title>`** = the recipe title (not "Cellar"); `robots: noindex, nofollow` (G7).
- **Absent by design** (assert in T4/T7): photos (Q2), notes, ratings (average and control), Cook, Edit, Delete, Edit photos, Share, Save a copy, Convert to grid, Edit grid layout, search, user menu, tag links, owner name or email, any `/api/` call that needs a session, `localStorage` writes, `router.refresh()`.
- **Present**: title, source banner (when a source exists), `RecipeMeta` without source and without tag links (F1), the scale and unit controls, the grid/list toggle, the grid (with the phone `StepSheet`) or the list, the Print button and hint (T6), the footer sentence.

### 3.4 Keyboard path (public page)

Tab: banner source link → scale presets (one stop each) → unit button → Reset → Grid → List → Print → the `ScrollRegion` (one stop; arrows scroll) → step cells in DOM order (Enter/Space expands; on a phone the sheet opens and Escape returns focus to the cell). No skip link is added (there is no navigation to skip).

### 3.5 Hydration and storage

`PublicRecipeView` is a client component with `useState` for view mode, `useScale`, and the phone media query; nothing reads `localStorage` or cookies; server and client render the same initial markup (`isPhone` is `false` on the server and the grid/list choice settles after mount exactly as `RecipeView` does today, so the existing hydration spec pattern applies).

### 3.6 Uniform 404 appearance

The existing page: root layout (theme, lang), `<main class="mx-auto max-w-sm p-8"><p>This link is invalid or has expired.</p></main>`, `<title>` "Cellar". No heading, no link, no button. This is what a guest sees for a revoked or mistyped link and what a user sees for a bad invite link; nothing in slice A changes it (F7). The T16 pass may promote the `<p>` to an `<h1>` in that one file.

## 4. Print (requirement 4; T6; G11, G12, G25)

### 4.1 What is printed

Printing reproduces **what is on screen**: the current view mode (grid or list), the current scale factor and unit choice. The printed page contains, in order:

1. The recipe title (`h1`).
2. The source line: on the recipe page `RecipeMeta`'s "Source: {name}" (the URL printed after it in parentheses via a `::after { content: attr(href) }` rule on the link so paper keeps the address); on the public page the source banner (same URL rule).
3. The facts line (servings, prep, cook) and, when the scale is not 1x or units are flipped, the scale summary sentence ("Showing amounts at 2x: serves 16.", "Units: US.") so the paper says why the amounts differ from the original.
4. Tags as a plain comma-separated line ("Tags: dessert, cookies") and the description.
5. The grid (every section's table, section title above each) or the list.
6. When "Include notes when printing" is on (recipe page only): a "Notes" block after the grid, each note as "{Author or You} · {date} · {Only you | Shared}" on one line and the body under it (`white-space: pre-wrap`).

**Hidden in print**: header and navigation, the actions row (Cook, Edit, Delete, Edit photos, Share, Print, Edit grid layout, Save a copy), the scale and unit controls (the summary sentence stays), the grid/list toggle, the photos hero, gallery and manager, the rating panel, the notes section's interactive parts (form, buttons, markers as chips; the print block replaces the list), the "Shared by" and cover-failed notices, the step detail panel or sheet, the `ScrollRegion` fade and arrow, the footer sentence of the public page (paper does not need it; the source line already attributes), the state chip. Anything with `aria-hidden` decorative icons prints as nothing.

### 4.2 The Print button and the landscape hint

- **Print** (`btn`, printer icon + text "Print", a real `<button>`, 44 px on coarse pointers) calls `window.print()`. Position: the actions row on the recipe page (after Share; readers: after Save a copy); the controls row next to the grid/list toggle on the public page (section 3.2).
- **Hint**: "Landscape fits the grid on one page." as `aria-describedby` of the button at every width; **visible** as muted text beside the button from 640 px up (phones print through a share sheet where orientation is chosen later; the hint would only cost a line). It is not a live region.
- `@page { size: landscape; margin: 10mm }` makes Chromium preselect landscape; Firefox and Safari ignore `size`, hence the hint. Only Chromium PDF is measured (T7); other browsers are "not tested" in the carryover.

### 4.3 "Include notes when printing" (G12; F6)

- A native checkbox with the visible label "Include notes when printing" in the **Notes section header**, right of the "Notes (n)" heading (wraps under it at 375). Rendered only when the viewer has at least one visible note (nothing to include otherwise). Component state in `Notes.tsx`, default **off**, not persisted.
- When on, `Notes.tsx` renders a print-only block (`hidden print:block`) listing the viewer's visible notes as in 4.1 item 6 and hides its interactive list in print. When off, nothing about notes prints.
- The public page has no notes and no checkbox (G12).
- Keyboard: it is one more tab stop after the Notes heading region; Space toggles; no announcement beyond the native checkbox state.

### 4.4 Fitting one page: font steps and the overflow rule (G11)

- The grid root carries `data-cols="{n}"`, `n` = the largest number of column steps in any section (`maxColumnsInSection`). The print stylesheet steps the table font by `n` (T0 spike 2 fixes the numbers; placeholders from G11):

| `data-cols` | Table font | Cell padding | Ingredient column |
| ----------- | ---------- | ------------ | ----------------- |
| 1 to 6      | 11 pt      | 6 px 8 px    | 62 mm             |
| 7 to 10     | 9 pt       | 4 px 6 px    | 52 mm             |
| 11 or more  | 7 pt       | 3 px 4 px    | 44 mm             |

- `.rg-scroller { overflow: visible; border-radius: 0 }`, `.rg-table { width: 100%; min-width: 0; table-layout: fixed }` so every column is on paper (no clipping); step columns share the remaining width equally; labels wrap (`overflow-wrap: anywhere`); the sticky ingredient column becomes `position: static` with its `box-shadow` replaced by a right border; the hidden `thead` stays zero-height (it is for screen readers, not paper).
- Borders and spans: `border-collapse` stays `separate`, every cell keeps its 1 px `--rg-line` borders and the outer 2 px frame; `rowSpan` cells print as drawn. `tr { break-inside: avoid }` so a row is never cut; `.rg-table { break-inside: avoid }` is applied **only** when the table is shorter than one page (CSS cannot know that, so the rule is: `section { break-inside: avoid }` is on by default and the browser ignores it when a section is taller than a page, which is exactly the fallback wanted).
- **When it still cannot fit** (more rows than a landscape page holds at the smallest step, about 30 ingredient rows at 7 pt, or several long sections): the grid prints on **as few pages as possible**: no forced page breaks between sections, rows never split, the font never goes below 7 pt, and each continued table starts at the top of the next page. No "continued" caption is added (out of scope). The README states the threshold measured in T0 spike 2 (both seed samples must be one page, G25).
- The list view prints as two stacked lists per section (Ingredients, Steps), 11 pt, no special rule.

### 4.5 Light theme forced (F4)

Under `@media print`: `:root, :root[data-theme='dark'] { color-scheme: light; --rg-surface: #ffffff; --rg-ink: #1f2a1f; --rg-muted: #4d5b4d; --rg-line: #3f7a25; --rg-banner: #eef5e9; --rg-empty: #f4f7f1; --rg-step: #e3f0da; --rg-accent: #3f7a25 }` (the `prefers-color-scheme: dark` block is overridden by the same selector list inside the print media block). Then `body, body * { color: #1f2a1f !important; background-color: transparent !important; box-shadow: none !important; text-shadow: none !important }` to beat the Tailwind `dark:` utilities, followed by the grid fills re-applied with `print-color-adjust: exact` (`.rg-table td.rg-banner { background-color: var(--rg-banner) !important }`, same for `.rg-step`, `.rg-empty`, the section frame). Links print underlined in the ink colour. The line colour is darkened one step in print (`#3f7a25` instead of `#5b9a3c`) so thin borders survive greyscale printers.

### 4.6 Keyboard path (print)

Tab to **Print** → Enter/Space opens the browser's print dialog (its own keyboard model). Tab to **Include notes when printing** → Space. Nothing else.

## 9. Legal review (support-legal-compliance-checker, 2026-11-15)

**Verdict: APPROVED WITH EDITS.** Summary of the opinion (general principles, not legal advice; EU/Belgium owner, worldwide visitors, private non-commercial self-hosted tool):

- Facts versus expression matters: ingredient lists and the bare method are not protected; descriptions and the specific wording of steps may be; photos are (correctly excluded from the public page). The draft "Recipes ... may be protected" overstated; the approved body names "the text of a recipe (descriptions, steps)".
- Attribution does not cure infringement; a source link is good practice (paternity) but not a defence, so the warning keeps the owner-responsibility sentence (treated as **mandatory** for informed consent). No no-ownership statement is needed in the dialog; the "not affiliated" clause belongs on the public page. A takedown contact and an imprint are **not required** for a private individual; the project must not hard-code a contact because it is not the publisher.
- "All users" on a private instance is a closed circle, close to the private-circle exception, and unlikely to be "communication to the public"; the public link is. Legal recommends the warning for the public link only, with at most a one-line "Imported from {source}" hint for All users. **Spec decision (F2)**: one static notice above both sections, because the tasklist binds both triggers and a static notice interrupts nobody twice; flagged for the PM (section 11, item 2).
- `noindex` is a request, not a guarantee: the owner text says "Search engines are asked not to index it", never "is not indexed". `no-referrer` is a privacy measure and is not mentioned to the owner. The draft footer claim "not indexed by search engines" was dropped as an overclaim to visitors.

**Final strings** (applied in sections 2, 3 and 10): warning title "This recipe was imported and not edited"; warning body and fallback body as in section 2; banner "Recipe from {source}. Shared read-only via Cellar, not affiliated with the source." with `{source}` a link to `source_url` when set (host name as fallback text) and plain text when only `source_name` exists; footer "Shared read-only link from a private recipe book."
