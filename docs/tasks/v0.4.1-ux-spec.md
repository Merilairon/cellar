# v0.4.1 UX spec: grid editor (T1)

Scope: slice 4b, weekend 1 (T1). Design only, no code. Read against `v0.4.1-tasklist.md` (requirement 5, G1 to G15, Q1 to Q13 as accepted by the owner on 2026-11-07, T1 to T9), `milestones/04-search-edit.md` req 5, `docs/prototype/grid-prototype.html` ("Edit spans"), `v0.3.1-ux-spec.md` (format model), `src/components/recipe/RecipeGrid.tsx`, `ScrollRegion.tsx`, `StepDetail.tsx` (native `<dialog>` sheet), `ConvertToGrid.tsx`, `styles.ts`, the `--rg-*` tokens and `.rg-*` classes in `src/app/globals.css`, and the `recipe.*` message naming in `messages/en.json`.

Principles: no new dependency; existing tokens first (`btn`, `btnPrimary`, `btnDanger`, `input`, `--rg-*`), new tokens only where listed in section 17; every action has a keyboard path and a non-drag path; nothing depends on colour alone; all user text (ingredient names, step labels, section titles) is a React text node; one polite live region; undo is the safety net, dialogs are the exception (Q2).

## 1. Modes, entry, chrome (decision area 1)

**States**: `view` (recipe page as today), `edit` (editor replaces the read view), `saving`, `conflict` (409 panel), and sub-states `clean` / `dirty` (differs from last save, Q9).

**Entry points** (owner/admin only, `recipe.can_edit`):
- **Edit grid** button in the recipe action row (`RecipeActions`), after "Edit" ("Edit" keeps meaning the recipe form). Shown only when `view_mode === 'grid'` (Q5), regardless of whether the visitor currently views Grid or List. List recipes show only the existing **Convert to grid** (section 16).
- After Convert to grid succeeds: a status line "Saved as grid." with a link-styled button **Fine-tune in the editor** (Q5), see section 16.

**What the page shows while editing**:
- Title and meta stay (read-only, one line "Editing the grid. Title, times and tags are changed with Edit." as muted text, key `gridEditor.scope`).
- Scale controls, unit toggle, view toggle, Edit, Delete, step detail panels: **hidden** (not disabled; fewer stops). A muted line: "Showing quantities as written (1x, original units)." (F3).
- The editor chunk is dynamically imported on click; button shows `aria-busy` and focus stays on it until the chunk mounts, then focus moves to the editor heading (`h2` "Grid editor", `tabindex=-1`).

**Toolbar** (sticky, `top: 0` under the app header at all widths, `z-index` above the sticky ingredient column, solid `--rg-surface` with a bottom border so tables do not show through):

```
>= 640 px:  [Undo] [Redo]   * Unsaved changes        [3 problems] [Cancel|Done] [Save changes]
 < 640 px:  row 1: [Undo] [Redo]   * Unsaved changes
            row 2: [issues: 1 warning v]        [Cancel|Done] [Save changes]
```

- Order left to right matches the tab order. Undo/Redo: icon + visible text at >= 640, icon + text also at phone (44 px each, text "Undo", "Redo"; `aria-label` adds the target, section 10).
- **Dirty indicator**: a dot icon + text "Unsaved changes" when dirty, "All changes saved" when clean after a save, nothing before any edit. Both are real text. The text is inside the `role="status"` region only on transitions (section 15), not re-announced.
- **Save changes** (`btnPrimary`): disabled when clean, when errors exist, or while saving. A disabled Save is `aria-disabled="true"` with `aria-describedby` pointing at the reason ("Fix the 2 problems first" / "No changes to save") so it stays focusable and explains itself.
- **Cancel / Done** share one slot (F2): "Done" when clean (closes, back to the read view, no prompt); "Cancel" when dirty (inline confirm, section 13). The control's accessible name changes with state; it is not announced on change.
- Issues button/disclosure: see section 11.

Rules:
- Tables keep the real `<table>`, `<caption>`, `scope`, rowspan semantics, sticky ingredient column (`th.rg-ing`) and `ScrollRegion` (labelled region, sideways scroll, fade/arrow). Editor widths: phone 138 px (unchanged), tablet 190 px (unchanged), desktop 340 px (was 300; room for the inline buttons). Step columns keep `min-width` 68 / 76 / 96; the editor adds 8 px of horizontal padding for the handle gutter at >= 640.
- Section toolbars sit **above** each table, outside the `ScrollRegion` so they never scroll sideways and stay reachable. They wrap (`flex-wrap`) and stack full width at 375.
- The inline "Adjust rows" panel and the step text panel render **under the section's table** (like today's `rg-detail`), full container width, not inside the scroller.
- Issues panel is below the last section at >= 640 and in a toolbar disclosure at phone; both show the same list (section 11). On phone the disclosure opens inline under the toolbar (pushes content, no overlay).
- No vertical max-height anywhere (no nested scroll traps). The page scrolls; the toolbar is the only sticky chrome.
- Print: the editor is hidden (`@media print` hides `.ge-*` chrome; the read view is what prints).

## 3. Table in edit mode: anatomy (decision area 2)

**Ingredient cell** (`th scope="row"`, class `rg-ing ge-ing`):

```
>= 900:  [ 1 ] sugar, half  — portion 1 of 2         [^] [v] [...]
640-899: [ 1 ] sugar, half                            [...]
< 640:   1 sugar, half                                (whole cell is one button -> row sheet)
```
- Row number: small tabular-nums text, `aria-hidden` (the name carries position through the roving label, section 14). It exists because span steppers talk in "row n".
- The name text is the `IngredientCell` display (stored primary measure, no scaling). It is the roving focus target of the row: a `<button>` with accessible name "Row 3 of 9: 3 tbsp butter" (the visible text plus position). Enter / F2 starts inline edit (section 7).
- Portion rows show the portion label inline (", half") and a text chip "Portion 1 of 2" so the split is not conveyed by colour or indentation alone.
- Inline buttons at >= 900: **Move up** (`aria-label` "Move {name} up"), **Move down**, **Row actions** (menu button, `aria-haspopup="menu"`, `aria-label` "Row actions for {name}"). 36 px tall and wide, 44 px with `(pointer: coarse)`. Move up on row 1 and Move down on the last row are `aria-disabled="true"` (stay focusable, no silent no-op: pressing announces "{name} is already the first row").
- Drag-grip for ingredient drag reorder is a **stretch (E2)**: a 6-dot grip left of the number, `touch-action: none`, same snap/Escape rules as span handles. Buttons and Alt+Arrow stay the primary path.
- Uncovered row: dashed 2 px `--ge-warn` outline on the cell, a "!" triangle icon, and sr-only text "Not used by any step" (shape + text + colour).
- Covered rows of the **selected step** get the live highlight: a 6 px solid `--rg-accent` bar on the cell's left edge, a `--ge-cover` tint, and bold name (shape + weight + tint). Also `aria-describedby`-free; the covered names are spoken by announcements, not by every cell.

**Step cell** (`td.rg-step.ge-step`, `rowSpan` as in the read view):
- Contents: label (`rg-lbl`), params (`rg-par`), the sr-only "Uses x to y" text from `recipe.grid.stepRows` (reused key), and a single `<button class="rg-stepbtn">` as the roving target with name "Step 2: Mix, rows 1 to 4. Press Enter to edit." (`gridEditor.step.cellLabel`).
- **Assertion kept from T8**: at phone width the cell contains **exactly one control** (the step button). Handles and per-cell menus do not render at < 640 px.
- At >= 640 px two **span handles** appear: top handle centred on the cell's top border, bottom handle on the bottom border. Visual: a 28 px wide, 6 px thick rounded bar (white 2 px outline so it reads on both tints) centred horizontally with a 12 px grip notch; shown on hover, on focus within the cell, and always for the selected step. They are `role="slider"` elements (section 4.4) with a hit area of 36 px height (44 coarse) and full cell width, `touch-action: none`, `cursor: ns-resize`.
- Selected step: existing `data-selected` outline (3 px `--rg-accent`, `outline-offset: -3px`); selection is also stated in text in the panel heading.

**Banner rows** (`td.rg-banner`, `colSpan`): the full-width banner shows `detail || label` and params exactly like the read view, plus at >= 640 a trailing icon-less text button "Edit" (accessible name "Edit banner {label}"); the banner text itself is a single roving button (Enter opens the banner panel: label, detail, temp, time, Move up / Move down inside its group, Convert to step, Delete). On phone the banner is just the one button; the panel is the sheet. Top banners render above the first ingredient row, bottom banners below the last, as in the read view. An **empty** banner (no label) is shown as muted placeholder text "(empty banner)" and counts as an error only if the schema forbids it (label required: open item O2).

**Between-row insertion**: no hover-insert lines (not touch friendly). "Add row" is a section-toolbar button (adds after the focused row, else at the end) and a Row actions item ("Add row below").

**Live uncovered warning**: below each table a `rg-detail`-style line (not the live region itself): "Not used by any step: eggs, flour" with text and the "!" icon, rendered whenever `row_uncovered` exists for that section. The polite region announces only transitions (when the set of uncovered rows changes after an action, once). Example transitions: "Warning: eggs is not used by any step." / "All ingredients are used by a step."

## 4. Span editing at tablet and desktop (decision area 3)

### 4.1 Handle shape and hit areas
Section 3 describes shape. Hit area: 36 px tall (44 px with `(pointer: coarse)`), full cell width, centred on the boundary (18 px or 22 px inside, same outside). Because the outside half overlaps the neighbouring non-step cell, pointer events on that strip belong to the handle (z-index above table cells, below the sticky ingredient column so a handle never covers the first column).

### 4.2 Drag behaviour
- Pointer down on a handle: `setPointerCapture`, step becomes selected, drag starts after 3 px movement (a click without movement does nothing, T6 acceptance).
- **Snapping**: the dragged edge snaps to the nearest row boundary (computed from the table's row rects, pure helper `rowFromY`). Top handle snaps to a row top, bottom handle to a row bottom.
- **Feedback during drag**: a 2 px dashed `--rg-accent` outline of the **proposed** span is drawn over the grid, covered ingredient cells take the live highlight (section 3), and a tooltip near the pointer reads "Rows 2 to 5" (text, `aria-hidden`; the live region does not speak during the drag). The committed state is unchanged until pointer up.
- **Clamping**: the top handle cannot pass the bottom handle (minimum span one row), both stay inside `0..n-1` of the section. Dragging past the table edge clamps without error.
- **Commit**: pointer up dispatches one `stepSetSpan` (one undo step), then one announcement (4.3).
- **Cancel**: Escape, `pointercancel`, or releasing outside the document restores the previous span without a history entry. Escape during a drag is consumed (it must not also close a sheet or panel).
- **Auto-scroll**: while the pointer is within 48 px of the top or bottom edge of the viewport, the window scrolls at up to 20 px per frame (proportional to proximity); horizontal scroll is not needed during a vertical drag. The sticky toolbar height is subtracted from the top zone.
- **Touch**: handles are active only on the selected step (F5); `touch-action: none` on the handle only, so one-finger scroll on the cell body and the rest of the table still scrolls. Long-press is not used.
- Reduced motion: no animated snapping (`prefers-reduced-motion`); the tooltip and outline are instant anyway.

### 4.3 Keyboard equivalent (Q4)
With a step cell focused (roving target, section 14):

| Key | Effect |
| --- | --- |
| `Alt+ArrowUp` | Top edge up one row (grow upward; `row_start - 1`) |
| `Alt+ArrowDown` | Top edge down one row (shrink from the top; `row_start + 1`) |
| `Shift+ArrowDown` | Bottom edge down one row (grow downward; `row_end + 1`) |
| `Shift+ArrowUp` | Bottom edge up one row (shrink from the bottom; `row_end - 1`) |
| `Alt+Shift+ArrowUp/Down` | Move the whole span up / down one row (same length); cut candidate E3 |
| `Home` / `End` on a step | Not used; arrow keys move the roving focus (section 14) |

- At a limit (span would be 0 rows or leave the table) nothing changes and the polite region says "Mix already starts at row 1" / "Mix must cover at least one row" (a no-op is always explained, never silent).
- Chords are chosen so that a plain arrow only moves focus, and so that Shift (selection) and Alt (modify) are consistent across steps and rows (Alt+Arrow moves things in the table, Shift+Arrow resizes the bottom).
- Mnemonic hint under the section toolbar and in the step panel: "Resize: Alt+Up or Down moves the top edge, Shift+Up or Down moves the bottom edge." (`gridEditor.hint.resize`). It is also in the help dialog-free "Keyboard help" disclosure (section 14).
- macOS: Option is Alt. `Alt+Arrow` is not a browser shortcut for Up/Down; Alt+Left/Right is (history) and is not used.

### 4.4 Handles as sliders (assistive tech and pointer)
Each handle: `role="slider"`, `aria-orientation="vertical"`, `aria-valuemin=1`, `aria-valuemax=n`, `aria-valuenow` (1-based row), `aria-valuetext` "Row 3: butter", `aria-label` "{label}, start row" / "{label}, end row" (T6: label included), `tabindex="-1"` (not in the tab order; section 14 explains why). When a slider is focused (screen reader browse or touch SR gesture): `ArrowUp/Down` move that edge one row, `PageUp/PageDown` five rows, `Home/End` to the section start/end, within the clamp rules. Their results are announced as in 4.5.

### 4.5 Announcement of the result
After every span change from drag, keyboard, slider or stepper, **once** (coalesced within 400 ms): "{label} now covers rows {a} to {b}: {first name} to {last name}." Single row: "{label} now covers row {a}: {name}." With more than 4 rows the names are first and last only. Example: "Mix now covers rows 1 to 4: butter to espresso." If a change leaves rows uncovered, the uncovered transition message is appended in the same announcement.

## 5. Phone bottom sheet (< 640 px) (decision area 4)

**Trigger**: a tap (or Enter/Space) on a step cell button. The step becomes selected, the sheet opens, the grid behind highlights the span live. Also opened for banners (reduced content) and for an ingredient row (row sheet, section 7).

**Component**: native `<dialog>` + `showModal()` via the shared sheet primitive (F6): focus trap, Escape closes, `aria-modal` implied by the modal dialog, `aria-labelledby` the step heading, background inert and scroll-locked (verify the existing lock; if it only relies on `dialog` modality, add `overflow: hidden` on `body` while open and restore after). Backdrop `rgba(0,0,0,.18)`; clicking the backdrop closes (same as read view); closing never discards a change (each stepper press is already applied and undoable).

**Layout** (stepper mode, max height `55dvh`, own vertical scroll if content exceeds it; border radius 16 px top):

```
+--------------------------------------------+
| Mix (step 2)                         [Close]|   heading + close (44 px)
|                                            |
| Start row        [ - ]  Row 1 of 9  [ + ]  |   group "Start row"
|                  butter                    |
| End row          [ - ]  Row 4 of 9  [ + ]  |   group "End row"
|                  espresso                  |
|                                            |
| Covers 4 rows                              |
|  1 butter                                  |
|  2 sugar                                   |
|  3 eggs                                    |
|  4 espresso                                |
| (!) Not used by any step: flour            |   only when the section has uncovered rows
|                                            |
| > Step details (label, text, time)         |   closed disclosure
| More: [Move left] [Move right] [To banner] [Delete step] |
+--------------------------------------------+
```

- **Steppers**: a `role="group"` with `aria-labelledby` "Start row"; inside: `[-]` button, a value `<output>` ("Row 1 of 9" plus the ingredient name on a second line), `[+]` button. Buttons are 44 x 44 minimum (not conditional on pointer at phone), `aria-label` "Start row: one earlier" / "Start row: one later" (and End equivalents), repeat-on-hold is **not** implemented (accidental runaway; Page up/down are not needed at <= 9 rows; open item O5 for 40+ row sections: optional `Start row` number input fallback).
- **Rules (the same as the keyboard)**: Start `-` stops at row 1; Start `+` stops at End; End `-` stops at Start; End `+` stops at the last row. A stepper at its limit is `aria-disabled="true"` (focus is kept), with visible reason text under the group while the button is pressed or focused: "Start cannot go past End." / "Already the first row." (keys `gridEditor.stepper.*`).
- **Covered ingredient names**: an ordered list (`<ol start="{a}">`) of the covered rows' display names (primary text, portion label included), never truncated; if more than 8 rows, the list scrolls inside a 8-row-high box (`max-h`, labelled) so the steppers stay on screen.
- **Live highlight**: each press dispatches `stepSetSpan` immediately (reducer is the source of truth); the grid behind shows the new span highlight (section 3) with no extra confirm. There is no "Apply" button; Close just closes. Undo is reached after closing the sheet.
- **Keeping the span visible**: after each change the grid scrolls (`scrollIntoView`-equivalent, instant under reduced motion, otherwise smooth, `block: 'nearest'`) so that the **edge just moved** is inside the visible region above the sheet. The visible region is the visual viewport height minus the sheet's measured height. The sheet is capped so at least 40% of a 667 px high viewport (about 267 px) of the grid stays visible: 55 dvh sheet leaves 45%. Horizontal: the selected column is scrolled into view once on open (below the sticky ingredient column; `scroll-padding-inline-start` already 146 px at phone).
- **Details disclosure** ("Step details"): contains Label (`input`, required), Detail (`textarea`), Temperature (value + unit select `C`/`F`, same fields as `StepsEditor`), Time from/to minutes. Closed by default so opening the sheet to adjust a span never shows a keyboard. When any of these fields is focused: the sheet may grow to `85dvh` using `visualViewport` (set a CSS variable `--ge-vvh` from `visualViewport.height`), the focused field is scrolled into view inside the sheet, and the Close button stays reachable by keeping the heading row `position: sticky; top: 0`. Text typed is coalesced for undo (`groupKey`). Tested at 375 x 667; real on-screen keyboards remain "not tested on a real device" (Q11).
- **More actions** row: Move left, Move right (disabled at ends with reason), Convert to banner (asks top or bottom through a two-button choice inside the sheet; default per G8; see 8.4), Delete step (immediate, with Undo toast in the page, Q2: the sheet closes after delete and focus goes to the toast's Undo, section 10).
- **Focus**: on open, focus goes to the sheet heading (`tabindex=-1`) so the first announcement is the step name and rows; Tab then reaches Start `-`, Start `+`, End `-`, End `+`. On close (Close, Escape, backdrop) focus returns to the originating step button (the roving target); if the step was deleted, to the section's first roving target and the Undo toast announces.
- **Banner sheet**: heading "Banner: {label}", fields Label, Detail, Temperature, Time; Move up / Move down (within top or bottom group); Convert to step; Delete. No steppers.
- **Column step sheet in landscape / short viewport** (< 480 px high): cap 70 dvh; steppers and list still reachable by scrolling inside; accepted.

## 6. "Adjust rows" on touch tablets and desktop (decision area 4b; G14)

At >= 640 px every step has an **Adjust rows** button in its toolbar (the step panel under the table, section 8.1), visible whenever the step is selected. Presses toggle an inline panel (not a sheet) that is the same component as the phone sheet's stepper block:

```
Mix (step 2)   [Adjust rows ^]  [Move left][Move right][To banner][Delete]
  Start row [-] Row 1 of 9, butter [+]     End row [-] Row 4 of 9, espresso [+]
  Covers 4 rows: butter, sugar, eggs, espresso      (!) Not used by any step: flour
```
- Targets: 36 px, 44 px under `(pointer: coarse)`; labels as on the phone.
- A touch tablet user is never required to drag: handles are optional sugar. Tapping a step selects it and reveals the panel's toolbar; "Adjust rows" is one tap away.
- The panel is a `region` (`aria-labelledby` the step heading), not a dialog (no focus trap; the table stays operable beside it so the live highlight is directly visible). Opening it keeps focus on the "Adjust rows" button (disclosure pattern, `aria-expanded`/`aria-controls`); the user tabs into the panel.
- The desktop also uses it (it is simply the labelled non-drag path).

## 7. Ingredient actions (decision area 5)

All actions live in: inline buttons (>= 900), the **Row actions** menu (640+), the **row sheet** (phone), keyboard chords. The menu (`role="menu"`, buttons `role="menuitem"`, arrows, Escape returns focus to its button) and the row sheet list the same items in this order:

1. Edit text (Enter, F2)
2. Move up (Alt+ArrowUp), Move down (Alt+ArrowDown)
3. Add row below
4. Split into portions (hidden if the row is already part of a group)
5. Rename portion (only for portion rows)
6. Delete row (Delete key)

**Reorder (Q1, G6)**: Move up/down swaps with the neighbour; spans follow the ingredient (hull rule); announcement "Butter moved to row 3 of 9." plus, when a span widened, " Mix now covers rows 1 to 5." Row focus stays on the moved row (it keeps the roving target by client key). Moving across a section is not possible (G7 rule 6; no control exists).

**Inline text edit (Q7, G11)**: Enter / F2 / click on the name turns the cell into one `input` (single line, `aria-label` "Edit ingredient {n}", prefilled with the composed text of the primary measure), and a **parsed preview** line under it: "Parsed as: 3 tbsp · butter · softened" (qty+unit · name · note; `aria-live` off, but `aria-describedby` on the input so it is read on focus; updated after 200 ms idle, visual only). Commit with Enter or blur (one reducer action `rowEditText`; C7 rule: if quantity/unit text changed the non-primary side is cleared). Escape cancels with no history entry and returns focus to the row button. Parse fallback: the typed text becomes the name with no quantity, and the preview says "Could not read a quantity; saved as a name." On phone the same input lives in the row sheet (Edit text block at top), with Done = Enter. Empty text on commit is rejected: keeps the old text and announces "An ingredient needs a name." (never creates a nameless row).

**Add row below**: inserts a blank row after the focused row (end of section when none), opens inline edit on it immediately; committing empty text removes the just-added row (cancels). Inserted inside a span: covered by that step (G6c); at an edge: uncovered, warning appears. Disabled at 200 rows with visible text "A section can have at most 200 ingredients." (key `gridEditor.limit.ingredients`).

**Delete row**: immediate, no dialog (Q2); toast with Undo (section 10); if the row was a step's only row the step is removed too and the toast says so: "Removed butter and the step Melt that only used it." Focus goes to the next row's button (or previous when last).

**Split into portions (G7)**: inserts a second row directly below; both rows share the group; quantities halved when numeric; labels "half" and "remaining". Focus goes to the new row's portion label field (a small input in the row, `aria-label` "Portion label for {name}") so the user can rename right away. Announcement: "sugar split into two portions: half and remaining." Chip "Portion 1 of 2" appears on both. Deleting one portion leaves a one-row group (the chip disappears; the "join" action is E4). Disabled at the 200 cap.

## 8. Step actions (decision area 6)

### 8.1 Step panel (where the step's fields and actions live)
Selecting a step (click, Enter, or on phone the sheet) shows the step panel under its section's table (>= 640) or the sheet (< 640). Contents in order: heading "Step {n}: {label}"; **Adjust rows** (section 6); fields Label, Detail, Temperature (value + C/F), Time (from/to minutes) reusing `StepsEditor` field components and error keys; action row **Move left / Move right**, **Convert to banner**, **Delete step**; keyboard hint. Typing coalesces for undo.

### 8.2 Add column step
Section toolbar **Add step**. New step: appended as the last column, label "New step" (key `gridEditor.step.newLabel`, not saved as a placeholder if the user renames it), span = the focused ingredient row if one is focused, else the first uncovered row, else row 1 (single row). It is selected, the panel opens (phone: sheet), and focus goes to the Label field with its text selected so typing replaces it. Announcement: "Step added: New step, covering row 3: eggs." Disabled at 100 steps per section with text.

### 8.3 Delete step (Q2)
Immediate, no confirm; toast "Deleted step {label}. Undo" (section 10). Focus: next step cell in the same column order, else previous, else the section's first ingredient row. If it was the last column step: the pre-save notice for `view_mode` (section 12.5) appears in the issues area immediately, not only at Save.

### 8.4 Convert to banner and back (G8)
Convert to banner: a two-option inline choice "Top banner / Bottom banner" (radio-like button pair, default per G8: bottom if the span ends at the last row, else top) with **Convert** and **Cancel**; sheet shows the same choice. Label/detail/temp/time preserved; the span disappears; announcement "Mix is now a bottom banner." Banner to step: **Convert to step**: becomes the last column with the default span (first uncovered row, or all rows if none uncovered); announcement "Banner Rest is now step 5, covering rows 1 to 9." Both are single undo steps.

### 8.5 Reorder steps (G9)
Move left / Move right buttons in the panel and chords on a focused step cell: **`Alt+ArrowLeft` / `Alt+ArrowRight`** move the step one column left/right (symmetry with row Alt+Up/Down; browser history uses Alt+Left/Right only when focus is not inside a handled keydown: the editor calls `preventDefault` on these chords while a roving target is focused; if a browser still navigates back the unsaved-changes `beforeunload` guard catches it - accepted, listed as open item O4). Banners move within their group with the same buttons labelled "Move up / Move down". Announcement: "Step Mix moved to column 3 of 5."

### 8.6 Add banner
Section toolbar **Add banner** opens a two-item menu "Top banner / Bottom banner". The new banner has empty text and is selected with its panel open (focus in Label). Announcement "Top banner added." Empty banners are saved only if the schema allows (O2). Limit shares the 100-step cap.

## 9. Sections (decision area 7)

- Each section has a toolbar above its table: heading `h3` (level below the editor's `h2`) with the title (or "Section {n}" fallback text, `recipe.section`), **Rename** (turns the heading into an `input`, Enter commits, Escape cancels, `aria-label` "Section name"), **Delete section**, **Move up / Move down** (E5, cut candidate), and the section-local **Add row / Add step / Add banner** buttons.
- **Add section** below the last section: appends a section named with the next fallback, containing **one empty ingredient row in edit mode and no steps** (no column steps, so no span warnings). It starts with **zero rows**, and the "{title} has no ingredients" warning shows until a row is added; focus goes to the section's Add row button. Open item O2: if the schema requires at least one ingredient, start with one empty row in inline edit instead.
- **Rename**: empty title allowed only when exactly one section exists (schema/`RecipeGrid` fallback); otherwise the commit is rejected inline: "Give each section a name." Announcement on commit: "Section renamed to Frosting."
- **Delete section**: if empty (no rows, no steps) delete immediately with Undo toast; if it holds anything, an **inline confirm** replaces the toolbar buttons (not a modal): "Delete {title} with {n} ingredients and {m} steps? You can undo this." [Delete] [Keep] ; focus goes to **Keep**; Escape = Keep; after deletion focus goes to the previous section's heading (or next). Q2: this is the only dialog-like confirm. The last remaining section cannot be deleted: the button is `aria-disabled` with text "A recipe needs at least one section."
- **Limit** 20: **Add section** `aria-disabled` with text.
- **Order and tab stops**: sections stack in DOM order; each section is: heading+toolbar (a few stops), then the table (one roving stop), then its panel/warning line. **PageDown / PageUp** inside a table jump to the first roving target of the next / previous section (announces the section name through its label); this is the keyboard link between sections. Shift+Tab from a table returns to that section's toolbar.

## 10. Undo / redo and delete-with-Undo (decision area 8; Q2, Q9)

**Buttons**: Undo and Redo in the toolbar, `aria-disabled` when unavailable (focusable; pressing announces "Nothing to undo"). Each shows its target in the accessible name only: `aria-label` "Undo: moved butter down" / "Redo: split sugar" (action descriptions come from the reducer's last action label key, `gridEditor.history.*`). A visible count is not shown (history cap 100; a count invites anxiety); the tooltip (`title`) mirrors the aria-label.

**Shortcuts** (bound on the editor container, `keydown`): `Ctrl/Cmd+Z` undo, `Ctrl/Cmd+Shift+Z` and `Ctrl+Y` redo. **Not intercepted** when the event target is an `input`, `textarea`, `select` or `contenteditable` (native text undo wins, T4 acceptance); in that case undo applies after the field loses focus. Inside a field the user can press Escape (cancel edit) first. After a pointer or key undo, the roving focus returns to the affected cell if it still exists, else to its section's first target.

**Coalescing** (T2): consecutive edits with the same `groupKey` are one entry: typing in a step Label / Detail / Temp / Time fields (key = step key + field); the inline ingredient line commits as one action so needs none; a drag, a keyboard resize repeated within 1 s on the same edge, and repeated stepper presses on the same edge within 1 s are **not** coalesced (each press is its own undo step: predictable, and the cap is 100). Selection and focus are outside history.

**Delete with Undo (Q2)**: deleting a row, step or banner, or an empty section, shows a **toast** at the bottom (above the phone safe area, `role="status"` region is the global polite one, the toast is its visible twin): "Deleted {what}." + **Undo** button (44 px) + dismiss `x`. It stays for 10 s, pauses while hovered or focused, and is replaced (not stacked) by the next toast. The toast is also the focus fallback target: after a delete from a menu or sheet, focus goes to the **next logical roving target**, not to the toast, so keyboard users are not thrown; the toast's Undo is reachable with `Ctrl/Cmd+Z` as always and by Tab from the toolbar (it is placed right after the toolbar in DOM order). Toast text is also written to the live region once. Undoing from the toast restores focus to the restored element.

**Announcements** for undo/redo: "Undone: {action}." / "Redone: {action}." with the same action phrase, once.

## 12. Save outcomes (decision area 10)

### 12.1 Success
Save request in flight: Save becomes "Saving..." (`aria-busy`, disabled; second click ignored, T9). On 200: the page data is replaced by the response (new `updated_at`, new ids, G4), dirty clears, history is kept (Q9, F2), selection is kept by client key, toast-free status "Saved." in the live region, the toolbar shows "All changes saved". **Done** then returns to the read view (focus to the Edit grid button); the read view's expanded step is reset.

### 12.2 Validation 422
Map `errors[].path` back with the path parser; show the issue in the panel as errors (section 11), the Save button remains available again after the user changes something. Focus goes to the issues panel heading (not the first control, to avoid jumping inside a table) with the panel opened and a **Go to** on each item. All local edits stay. Unknown paths fall back to a generic "The server rejected this change: {code}." item (never raw JSON).

### 12.3 Network error / 5xx
Inline alert (`role="alert"`) in the toolbar zone: "Could not save. Check your connection and try again. Your changes are still here." [Try again] (focus goes to this button). Nothing is lost; dirty stays.

### 12.4 Conflict 409 (Q3)
Replaces the issues zone with a conflict panel (`role="alertdialog"`-free: a region with heading, focus moved to its heading): 
> **This recipe changed while you were editing.** This recipe was saved again after you opened the editor, maybe in another tab or by someone else. Your changes are not saved yet. The other version was saved at {time}.
> [Keep editing] (default, focused) · [Load the latest version] · [Replace their version with mine]

- **Keep editing**: dismiss the panel, editor stays; Save remains enabled and will conflict again until the user chooses one of the others; a muted line near the toolbar says so ("Saving will ask again because the recipe changed...", `conflict.keptNote`). (Users can copy text out of fields; there is no export, O3.)
- **Load the latest version and discard my changes**: first an inline confirm "This throws away your changes in the editor." [Discard and load] [Cancel]; on confirm, the editor re-initialises from a fresh GET, history cleared, "Loaded the latest version." announced.
- **Replace their version with mine** (was "Save mine anyway"): inline confirm "The other version will be replaced by yours." [Save mine] [Cancel] (danger style `btnDanger`); on confirm, re-send with `base_updated_at` = the `updated_at` from the 409 body. Never silent (Q3).
- The conflict panel never auto-shows twice for the same base; after the user picks, normal Save resumes.

### 12.5 `view_mode` becomes list (Q13, G3)
If the working state has **no column step**, an amber notice appears in the issues area at once (not only on Save): "This recipe has no step columns. It will be saved as a list." with [Add a step] (which runs Add step) as its action, and Save asks nothing more (the notice is the pre-save notice). After a successful save the read view opens in list mode and says so in the status line "Saved as a list."

## 13. Leave guard (decision area 10b; Q8, G15)

- **Dirty**: `beforeunload` is registered only while dirty (reload, tab close, browser back to another origin); the dialog text is the browser's (F9). No draft is stored anywhere (Q8).
- **Cancel** (dirty): inline confirm replaces the Cancel/Save group in the toolbar: "Discard {n} unsaved changes?" [Keep editing] [Discard changes] (danger). Focus goes to **Keep editing**; Escape = Keep editing; **Discard** closes the editor (history dropped) and focus returns to the Edit grid button. `n` = number of history entries since the last save (rough, "some" when unknown).
- **Done** is the same control when clean; there is no confirm.
- In-app navigation away (header links, recipe links): intercepted **only if** Next 16 exposes a supported hook (T9 reads the docs). If not, the gap is recorded: the user can lose edits by clicking a header link; mitigations: the sticky "Unsaved changes" dot, `beforeunload` for hard navigation. Open item O6.
- Browser back while dirty: treated as navigation away (same limits).

## 15. Screen reader and live-region policy (decision area 12)

- **One** polite live region (`role="status"`, `aria-atomic="true"`) at the top of the editor, visually hidden, rendered once with the editor (empty at mount). Nothing else on the page is `aria-live` except the existing `rg-detail` (not rendered in edit mode). The visual toast is `aria-hidden` (it duplicates the region) except its buttons.
- **Policy**: one announcement per completed user action; messages are queued and **replaced**, not appended, if a newer one arrives within 400 ms (so five rapid stepper presses read the last result). **No per-keystroke announcements**: typing in fields, parsed previews, drag movement, and hover tooltips are silent. Errors that block an action (a no-op at a limit, a rejected rename) use the same region. `role="alert"` is reserved for the network-failure and 409 panels.
- **Heard for common actions**: row moved ("Butter moved to row 3 of 9. Mix now covers rows 1 to 4: butter to espresso."), span resized (4.5), step added/deleted/converted (section 8), undo ("Undone: moved butter down."), save ("Saved."), warning transitions (section 3).
- **Table semantics** are preserved: `scope="row"` on ingredient cells, `scope="col"` on a hidden-but-present header row ("Ingredient", "Step 1: Mix"), caption per section; the roving buttons have explicit names that include position and span (`Row 3 of 9: ...`, `Step 2: Mix, rows 1 to 4`), so a user browsing with a screen reader and a user tabbing hear the same facts. Editing chrome buttons are real `<button>`s with names; icons are `aria-hidden`.
- **Handles** are exposed as sliders with `aria-valuetext` (4.4); they are not tab stops, so a keyboard user does not meet 2 extra stops per step; browse-mode users still find them.
- **Focus management**: every open/close/confirm states where focus goes (sections 5, 8, 9, 10, 12, 13); focus never lands on `body`; after any structural change focus is on a stable client key.
- **Reduced motion and zoom**: no essential animation; at 200% zoom / 320 px width the toolbar wraps and the table scrolls sideways (inherited from `ScrollRegion`).

## 20. Revision after the usability walkthrough (2026-11-07, owner decisions A and B)

Findings refer to `docs/tasks/v0.4.1-usability-check.md`. Where this section differs from an earlier one, this section wins.

- **Leave guard (F2, supersedes the O6 gap in section 13 for Back).** While the editor is dirty there is one extra history entry on top of the page's own (`pushState` without a url). Browser Back, the Android back gesture and the iOS edge swipe pop it; the editor pushes it again at once and shows the existing leave confirm (Keep editing is focused, Discard changes closes the editor and stays on the recipe page). The entry is removed when the document becomes clean (saved, undone to the saved state) and when the editor closes, so Done leaves no extra entry. `beforeunload` stays for reload and tab close. Not covered: the header links (logo, nav, user menu), which stay plain links; `<Link onNavigate>` is per link and would need a shared guard state across three header components, so this is a documented gap for carryover.
- **Steppers (F1).** Start row and End row use an up arrow (earlier row) and a down arrow (later row) on both, never `-` / `+`. The `aria-label`s are unchanged.
- **Conflict (F3).** Copy and time as in 12.4; the destructive choice is "Replace their version with mine"; after Keep editing a muted note explains that Save will ask again.
- **New step (F4).** On the phone sheet a new step or banner opens "Step details" and focuses and selects the label.
- **Sections (F5, F14).** Add section stores no title (the "Section N" fallback shows) and opens its rename field at once with the placeholder "Name this part, for example Frosting". An untitled section in a multi-section recipe shows "Name this part, for example Cake or Frosting." Emptying an existing name and leaving the field keeps the field open with "Give each section a name." (a blur on a section that never had a name just closes it).
- **Resize hint (F6).** Two hints chosen by `@media (pointer: coarse)`: touch "Tap a step, then drag the green bars, or tap Adjust rows."; otherwise the keyboard and drag text.
- **After a save (F8).** The toolbar shows a check mark with "All changes saved" and Done becomes the primary button (Save becomes secondary). The editor still does not close by itself.
- **Entry label (F12).** The entry button reads "Edit grid layout".
- **Only section (F13).** "A recipe needs at least one section." is read out with the disabled Delete section button (sr-only) and shown only after it is pressed.
- **Conflict and problems (F17).** The Problems panel stays rendered under the conflict panel so the toolbar count has a target.
- **Uncovered rows (F18).** Wording is "No step covers: {names}."
- **Tab stops (F11, audit A3, owner decision 2026-11-07).** The per-row Move up, Move down and Row actions buttons are `tabindex=-1`, so each table is one tab stop plus roving (38 stops became 2 on the cake sample). They stay for mouse and touch. Keyboard: `Alt+Up` / `Alt+Down` move a row; `Shift+F10` or the Menu key opens Row actions for the focused row (the row sheet on the phone; Escape returns to the row), and opens the panel on a step or banner. The Keyboard help disclosure (14.1 item 3, `gridEditor.help.*`) is built and sits right after the toolbar. It lists the 14.3 chords plus these two.
- **Audit A4, A5, A6.** The section rename error is no longer `role="alert"` (described by the field and sent to the polite region). The toast focus ring uses the toast ink (14.90:1 light, 12.72:1 dark). While a toast shows, the page keeps `scroll-padding-bottom: 9rem`, and Dismiss returns focus to the table.
- Not applied: F7, F9 (not measured at 375 px), F10, F15, F16 go to the carryover file.
