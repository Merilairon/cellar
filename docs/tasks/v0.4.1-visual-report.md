# v0.4.1 visual regression report (T13)

Scope: editor visuals at 375 / 768 / 1280, owner-page chrome baselines, diagnosis of the earlier
unexplained visual failures. Everything was rendered in the pinned image
`mcr.microsoft.com/playwright:v1.64.1-noble` (Node from `.nvmrc`), never on the host. The tasklist
named the evidence file `v0.4.1-visual-evidence.md`; this file is that note.

## 1. The earlier unexplained failures (search-visual list @375, import-visual review panel @375)

Method: the full e2e suite in the pinned image on a worktree of the `v0.4.0` tag and on the clean
v0.4.1 HEAD (0ecaad6), both on a fresh DB.

| Tree | Result |
| --- | --- |
| v0.4.0 tag | 131 passed, 0 failed. All visuals green, including both names above. |
| v0.4.1 HEAD (clean) | 2 real failures, 1 retry artifact, 14 did not run (serial group aborted). |

Findings:
- **Real, expected**: `recipes-visual` "sample A @375" and `search-visual` "recipe page ... @375"
  fail on HEAD because the owner page now has an "Edit grid layout" button. At 375 it wraps to its
  own row (+52 px, 990 -> 1042 and 1199 -> 1251). At 768/1280 only the 132 x 44 button box differs.
  This is a legitimate baseline change, not a regression.
- **list @375 was a retry artifact, not an independent bug.** `search-visual` is a serial group
  with a `beforeAll` that creates recipes. When one test in the group fails, the CI retry (`retries: 2`)
  re-runs `beforeAll`, which creates a second and third "cake" for the same user. The heading count
  assertion then sees 2, then 3 (`toHaveCount(1)` in "recipes list with search and tag chips").
  Run in isolation (auth + visual specs), the list test passes on its first attempt (225 ms) and
  fails only on retries (5.2 s). The cure is to fix the real failure, which regenerating the
  baselines does. Not a product bug.
- **import-visual @375 did not reproduce**: it passed on HEAD in the full run and in the subset
  run. I cannot prove what the earlier failure was; the same retry mechanism (a failing neighbour
  re-running a serial group) is the most likely explanation, but this is a hypothesis, not a
  finding.
- Not caused by the editor: v0.4.0 is green in the same image, and list-search / list-tag /
  import baselines are byte-identical after regeneration.

## 2. New visual spec

`tests/e2e/grid-editor-visual.spec.ts` (20 baselines in
`tests/e2e/__screenshots__/grid-editor-visual.spec.ts/`), Mocha Skillet Cookie, user `gevisual`.
Nothing is saved; the recipe is only edited in memory (409 is a route stub).

States: idle (3 widths, light; 375 and 1280 dark), selected step (3 widths light, 375 and 1280
dark), Adjust rows (768, 1280), phone row sheet (first row and last row), conflict panel (3
widths), issues panel with the "No step covers" warning (3 widths). No horizontal page overflow
outside the ScrollRegion is asserted at 375 (idle and selected step).

Two harness findings, documented in the spec:
1. Playwright `fullPage` capture flickers the emulated viewport: `(max-width: 639px)` flips for a
   moment on each capture (observed via a `change` listener). `useStepWiring` swaps StepPanel for
   StepSheet on that flip, so the Adjust rows disclosure closed at random (baseline 1947 px high in
   one run, 1826 px in the next; failed three times in a row, then passed when the timing changed).
   A real window resize does not do this (probed). Fix in the harness: make the viewport as tall as
   the document and take an ordinary viewport screenshot. After that, two consecutive verify runs
   of all visual specs were 45/45 green.
2. A `fullPage` capture also painted the sticky toolbar mid-page. Same fix.

## 5. Layout bugs found and fixed (minimal diffs)

1. **Phone step sheet covered the span it edits when it opened** (`StepSheet.tsx`, 3 lines). The
   scroll-into-view only ran after a span change. Now the first run treats the start row as
   "moved", so the sheet opens with the start row above it. The existing e2e (sheet, phone, a11y)
   stays green.
2. **Sticky toolbar and panel heading used `--rg-surface` (#1d241d in dark)**, a lighter band than
   the page (#0a0a0a) (`globals.css`, new `--ge-page` token for the toolbar and `.ge-panelhead`;
   the heading inside the bottom sheet keeps `--rg-surface`). Light mode is unchanged (both white).

Reported, not changed: the focus ring / no top margin on the "Grid editor" heading; the row sheet
hiding the row it acts on (last row); the "Edit grid layout" button sitting under the share
checkbox at 375.
