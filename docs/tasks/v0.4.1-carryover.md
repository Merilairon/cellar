## 6. Changelog lines (T16)

- **New endpoint:** `PUT /api/recipes/:id/grid` replaces a recipe's sections, ingredients and steps in one transaction. Body `{ base_updated_at, sections }`; 409 on a stale base, 422 on invalid structure, unknown keys rejected, every response `Cache-Control: private, no-store`. See the README "Grid editor" and `docs/data-model.md` section 5.
- **New UI:** **Edit grid layout** button on the recipe page of a grid recipe you own (admins: any). The owner page action row gained this button, so the owner-page chrome baselines changed (14 PNGs, visual report section 3). After **Convert to grid** a link offers to fine-tune in the editor.
- **Cache headers:** `GET /api/recipes/:id` (200, 404, 401) now returns `Cache-Control: private, no-store` (I1); the grid route sets it on every response.
- **`updated_at` is strictly later:** every recipe write (form PUT, grid PUT, visibility) now sets `updated_at` strictly after the previous value, even within one millisecond (L1).
- **Behavior:** after a grid save the server recomputes `view_mode` and issues new section, ingredient and step ids. Unsaved editor changes are guarded on reload, tab close, Cancel and browser Back.
- **Copy:** the import review explanation no longer says the editor is planned.
- **No new environment variables, dependencies or migration.** Verified for this file with `git diff v0.4.0 -- package.json package-lock.json src/lib/env.ts .env.example drizzle`: empty output (no file listed). `ls drizzle` ends at `0006_fts_defer.sql`. The security checkpoint records the same for `package.json` and `package-lock.json` against `main`.
