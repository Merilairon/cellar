**Flake diagnosis result (2026-11-16, pinned image, retries off).**
- **Cook-mode visual (`media-visual` "cook mode: unchecked and checked" at 1280 px): pre-existing.** It fails on tag `v0.4.2` too, with the same pixel counts (1732 px light, 1553 px dark): tag 1 of 5 then 5 of 5 failed alone, HEAD 0 of 5 then 5 of 5. The earlier 260/260 run on the tag state was luck, not proof of stability. Cause: the `.ck-wake` notice line appears late because headless Chromium rejects the wake lock asynchronously, and `.ck-wake:empty{display:none}` makes first-render layout depend on timing (two stable renders, 1 px apart). Fix applied in v0.5.0: reserve the line from first render and regenerate the cook baselines (see the commit).
- **Enter on Share did not reopen the dialog: real race in this slice.** Reproduced 1 of 10 alone and 4 of 20 with a probe. After Escape the native dialog is closed and focus is back on the button, but the `close` event reaches React about 10 ms later; a click in that gap runs `setOpen(true)` on state that is still true, then the late `close` event closes it. Fixed in v0.5.0 (see the commit); the test retry that masked it is removed.
- **`import-mapping-a11y` keyboard test: unestablished.** v0.4.2 0 failures in 8 runs, HEAD 1 failure in 13 runs (`toBeFocused` at line 217 of the spec), not diagnosed. The planned 10 extra loaded runs per side were not run. Treat as a possible load flake; re-run at the gate and name it if it recurs.

Deferred to the next slices: export and restore (v0.5.1, slice B: T9 to T13) and hardening, the security review, the accessibility pass, the README rewrite and the release checklist (v1.0, slice C: T14 to T18). `docs/data-model.md` section 6 (backup format) is still a draft and no export or restore route exists.

## 6. Changelog lines (v0.5.0)

- **New endpoint:** `POST` and `DELETE /api/recipes/:id/share-link` (create or replace the public link, revoke it). Owner or admin; CSRF-checked; `Cache-Control: private, no-store`; 403 `public_links_disabled` when links are off. `GET /api/recipes/:id` (and the create, update and grid-save responses) gain `share` (owner and admin only) and `public_links_enabled`. See `docs/data-model.md` section 5.
- **New route:** `GET /r/:token`, the public read-only recipe page (no sign-in; uniform 404; `Referrer-Policy: no-referrer`; `noindex, nofollow`; rate limited), and `GET /robots.txt` (`Disallow: /`).
- **New environment variables:** `PUBLIC_LINKS_ENABLED` (default `true`), `RATE_LIMIT_PUBLIC_MAX` (default `120`), `RATE_LIMIT_PUBLIC_WINDOW_SEC` (default `60`). Added to `.env.example` and the README table.
- **UI:** a **Share** dialog replaces the "Share with all users" checkbox; **Print** on the recipe and public pages; **Include notes when printing**; a print stylesheet.
- **Behaviour change:** changing a recipe's visibility (`PUT /api/recipes/:id/visibility`) no longer changes `recipe.updated_at`, and neither do the share-link actions. A grid editor session's `base_updated_at` stays valid across sharing changes, and the newest-first list order no longer moves when you share. An imported recipe that was only shared stays "unedited" for the copyright notice.
- **Deployment:** the app port must not be published when public links are on, the proxy must forward `X-Forwarded-For` and `TRUSTED_PROXIES` must list it, and the proxy must not cache `/r/*` ([../deployment.md](../deployment.md)).
- **No migration.** `drizzle/` still ends at `0007_note_rating_thumb.sql`; `recipe.share_token` and its unique index have existed since `0001`.
- **No new dependency.** `package.json` and `package-lock.json` are unchanged by slice A.


## Code review residuals (v0.5.0, [v0.5.0-code-review.md](v0.5.0-code-review.md): APPROVE WITH CONDITIONS)

- **m1, owner decision (provisional Q5 kept):** with `PUBLIC_LINKS_ENABLED=false`, `DELETE share-link` returns 403, so an owner cannot revoke a link while links are disabled, and the stored token works again if the flag is turned back on. The dialog hides the switch in that state anyway. Alternative: allow revoke while disabled. Recommendation: allow it in slice C hardening, since revoke is always safe.
- **m2, fixed:** the `share` parameter of `createRecipeFor`, `getRecipeFor`, `updateRecipeFor` and `updateGridFor` is now required.
- **m3, open:** print CSS uses structural selectors (`main > div.lg\:grid > div:nth-child(2)`) that depend on markup order. Safe today (all inside `@media print`); brittle if the recipe page layout changes. The print e2e would catch it.
- **m4, open:** the `SheetDialog` `open` guard has no unit test for its other users (grid editor, cook mode). The e2e suites for both passed.
- **Nits, open:** duplicate no-op case in `src/proxy.test.ts`; `linksEnabled` never set false in `routes.test.ts` (covered in `share-link.test.ts`); `limiterKey` in `public-limit.ts` is hard to read; footer class order in `PublicRecipeView.tsx`.
