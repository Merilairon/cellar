## Specification Summary

**Source**: [milestones/03-url-import.md](../../milestones/03-url-import.md) (slice 3a only), [RELEASE_PLAN.md](../RELEASE_PLAN.md) (Definition of Done, Test Corpus), [TASK_ASSIGNMENTS.md](../TASK_ASSIGNMENTS.md) (v0.3.x table, 03a rows, Gate, per-slice workflow), [data-model.md](../data-model.md) (§3 Import Pipeline and Safety, `photo`, `import_job`, §5 API), [v0.2-carryover.md](v0.2-carryover.md), [v0.2-tasklist.md](v0.2-tasklist.md) (format and conventions).

**Objective (quoted, 3a)**: "Static import: requirements 1-4 (static fetch and paste only), 6-9, with a basic review screen that saves in list view." "Requirements 13-14 apply from 3a." Slice objective: "Import a recipe from a URL: fetch -> parse Schema.org -> ... -> review -> save, with ... paste fallbacks" (headless and auto-mapper are later slices).

**In scope (spec requirement -> task)**: 1 SSRF guard -> T1; 2 JSON-LD extractor -> T3; 3 normalizer -> T4; 4 fallback chain, static fetch then paste only -> T5, T9; 6 API -> T6, T7; 7 UI, minus grid preview and confidence badge -> T10, T11; 8 duplicate detection -> T7 (check) and T11 (link); 9 cover image on save -> T8; 13 rate limit -> T6; 14 fixtures -> T12.

**Out of scope for 3a (do not build)**
- Req 5 and 12, auto-mapper `map-grid.ts`, section detection from "For the ..." headings, split ingredients, bottom banners, confidence score, live `RecipeGrid` preview: slice 3b (v0.3.1). In 3a every imported recipe saves with `view_mode = 'list'`; column steps have null spans (allowed in list mode, G5 of v0.2). `HowToSection` is flattened into steps; its name is prefixed to the step label only if cheap (see G8).
- Req 10 and 11, headless sidecar, `HEADLESS_URL`, Docker `browser` service, sandbox tests: slice 3c (v0.3.2). The `method` enum keeps `headless` as a legal value but 3a never writes it. The "blocked / no recipe" path goes straight to paste mode with a clear message.
- Microdata (`itemprop`) parser: spec says "if time allows". Cut line: not in 3a unless the fixture report is below 85 percent after T12 (see G9).
- Photo upload UI, photo gallery, multiple photos, `photo.position > 0`: M4 (04c). Only the cover image on import (req 9).
- Unit conversion, search, tags tables: 04a. Keywords are mapped to a draft `tags: string[]` and shown in review, but **not persisted** in 3a (no `tag` table until 04a). See G10.
- No AI/LLM calls, anywhere ("Do not add AI/LLM calls").

**Technical stack** (already in repo): TypeScript strict, Next.js 16 App Router, Tailwind 4, Drizzle + better-sqlite3, zod 4, next-intl (`messages/en.json`, enforced by `tests/unit/i18n-keys.test.ts`), Vitest, Playwright (port 3100, fresh DB, serial specs), tsx scripts. Existing reusable pieces: `src/lib/import/ingredient-parser.ts` (`parseIngredientLine`, `toIngredientFields`), `src/lib/security/rate-limit.ts` (`createRateLimiter`, env-driven `RATE_LIMIT_*` config in `src/lib/env.ts`), `src/lib/recipes/{schemas,service,http,access}.ts`, `src/lib/auth/csrf.ts`, `src/app/(app)/import/page.tsx` (placeholder, message "Recipe import is not available yet.").

**New dependencies** (decisions in G1 and G2): an HTML parser (cheerio, per TASK_ASSIGNMENTS row "Fetch, cheerio, JSON-LD parsing") and an image library (sharp, see G2).

**Build order (spec "Instructions for LLM")**: "Build `safe-fetch` first and test it before any other import code." "Make the extractor, normalizer and mapper pure functions that take strings/objects and return objects; fetching lives only in `safe-fetch.ts` and the headless client." "Sanitize all imported text (strip HTML tags/scripts) before storing or rendering." "Never store raw HTML permanently unless the `KEEP_RAW_HTML` env var is set." "Do not add AI/LLM calls."

**Hard rules**
- No import code (extractor, normalizer, routes, UI) is merged before T1 tests pass; T1 is a separate Conventional Commit.
- Network access only in `src/lib/import/safe-fetch.ts` (and the image download, which also goes through `safe-fetch`). Extractor, normalizer, sanitizer, pipeline are pure (no node `net`/`dns`/`fs`, no db imports).
- Data access only in `src/lib/db/`; no raw SQL in handlers; zod on all inputs; `isCsrfSafe` first on every mutating handler, then `getCurrentUser`, `Content-Type: application/json` required (415) as in v0.2.
- Failed imports never create a recipe (acceptance criterion). Only `POST /api/import/:id/save` writes to `recipe`.
- All imported text is untrusted: strip tags, decode entities once, collapse whitespace, length caps, before storing in `draft_json` and before rendering. React escaping stays on; no `dangerouslySetInnerHTML` anywhere in import UI.
- Fixtures contain extracted JSON-LD and minimal HTML only, not full copyrighted pages (req 14).
- No hard-coded UI strings or error messages shown to users; all in `messages/en.json` under `import.*`, including one message per `error_code`.
- No background processes or server start commands in task commands. Conventional Commit after each numbered task, no co-author trailers (owner's global CLAUDE.md).
