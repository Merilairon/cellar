## Findings

- **F1 (Medium, config/docs gap)**: `docker-compose.yml` passes an explicit env list and has no `env_file`, so `KEEP_RAW_HTML`, `UPLOADS_DIR` and any future import env var set in `.env` never reach the container. README (line 281) and `docs/deployment.md` document `KEEP_RAW_HTML=true` -> `/data/import-raw` as if it works with compose. It only works with `docker run -e` or a compose override. Default (off) is the safe state, so not a blocker. Fix: add `KEEP_RAW_HTML: ${KEEP_RAW_HTML:-false}` to compose (and document), or document the override.
- **F2 (Low, test gap)**: no e2e asserts "no hydration warning" on the recipe form or review screen; the f4368a1 regression is covered only by a unit test of key derivation. Add console-error capture to an import/review e2e.
- **F3 (Low)**: carried-over decisions still open and correctly recorded: `source_url` forced to https and cover http->https upgrade (review m1/m2, carryover section 2). Not 3a blockers.
- **F4 (Info)**: e2e server log is noisy with `cover failed: fetch_failed` lines; expected (fixtures), but they hide real ones.
