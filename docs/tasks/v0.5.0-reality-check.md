Not an acceptance criterion. Either fix the bundle or correct the two docs lines before the tag. For my checks I created the two samples by POSTing `SAMPLE_RECIPES` to `/api/recipes` (same data the seed inserts).
2. **Name the flake.** `import-mapping-a11y` "keyboard only: apply, edit, confirm with Esc ..." failed once in the full run (attempt 1, `toBeFocused` on `#map-preview-summary`, "inactive", reported at line 226) and passed on retry (Playwright "1 flaky"). Alone, 3 of 3 passed with retries off. Rate: 1 failure in the full run, 0 in 3 isolated runs; cause still undiagnosed. It is pre-existing as a test, but whether it also fails on `v0.4.2` was **not tested** here. Keep it listed as a known flake. Do not call the suite "0 flaky".
3. Owner items still open: Q15 real-device try; code-review m1 (revoke while `PUBLIC_LINKS_ENABLED=false` returns 403) decision; legal-scope decision on the copyright notice (carryover section 1). None blocks on evidence, but they are owner decisions, not done.

## Acceptance criteria, literally

1. **"Anonymous user can open a public link and nothing else; revoking the link makes it 404 immediately"**: **PASS.** A cookie-less client got 200 for `/r/<token>` and nothing private in it; `/recipes` redirects to login, `/api/recipes`, `/api/recipes/:id` and share-link are 401; the very next request after `DELETE` was 404; rotation 404s the old token at once. Same results through the production container, the upgraded volume and Caddy. Pinned-image `share.spec`, `public-page.spec` and `rate-limit.spec` passed.
2. **"Printing the sample recipe produces a single page with the grid intact"**: **PASS** for both samples, recipe page and public page, A4 and Letter landscape in Chromium (table above); pinned-image `print.spec.ts` passed.
3. R5 (sharing never changes `updated_at`): **PASS** (above).
